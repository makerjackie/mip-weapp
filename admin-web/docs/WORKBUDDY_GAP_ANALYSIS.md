# Workbuddy 原型差距分析

审计日期：2026-08-28。原型：[MIP 小程序后台管理系统 PRD V0.4](https://bfd568111f4249be9902eba8e876cece.app.workbuddy.link/#messages)。本文件只记录当前截图、导入基线、现有 module/service 与服务端文档能证明的事实；演示数字不视为生产能力。

## 总体结论

导入基线已经具备 14 个一级页面、8 类详情、AdminRequest v1、同源 BFF、短码会话、80 条查询和 80 条受审写 action，但展示层是约 1,700 行字符串 DOM、字符图标和逐函数事件绑定。当前版本已经用 React 路由、Query、Ant Design 与公共 UI 完成迁移，旧 `src/main.ts`、旧全局 `src/styles.css` 和字符串渲染函数已经删除。React 生产版本已从源码 `c182db2` 部署到 `https://mipmini.01mvp.com/`，Cloudflare Pages deployment ID 为 `6d3b4c88-31e9-452f-b27f-1a95209d8f00`。

已经直接解决的主要差距：React AppShell、蓝色渐变侧栏、分组导航、当前位置、消息入口、账号菜单、统一页面头/筛选/表格/抽屉/弹窗/标签、四项指标、趋势容器、待办、系统动态、快捷操作、手机抽屉导航和加载/错误/空/无权限状态。

当前 14/14 个已认证路由均已通过线上真实只读验收；真实 JPEG 上传、Banner 以 `INACTIVE` 保存并软删除，以及不含手机号的空结果用户导出也已完成生产闭环。不能从前端直接补齐的差距集中在仪表盘趋势序列、原型新增角色/账号体系、自由权限配置、短信、外部消息投递、AI/provider、支付和真机事实。运营记录读模型目前也不提供稳定的 `reportId` 与 `version`，因此举报结案入口保持关闭，避免伪造并发保护输入。

## 原型结构修正

- 手机端不保留固定桌面侧栏，改为抽屉导航。
- “后台账号管理”并入权限管理的账号/会话 section，避免引入未经确认的密码体系。
- “服务器”是产品 UI 对城市分会的习惯称谓，不代表新增通用服务器或租户模型；服务端模型、数据库表、`branch` 合同和数据范围保持不变。
- 状态与图标不使用原型字符符号，改用 Ant Design 图标和文字标签。
- 原型演示日期、人物、金额和趋势不进入真实模式。

## 需要业务确认

| 问题 | 影响 | 推荐默认方案 | 未确认时的可替换默认值 |
| --- | --- | --- | --- |
| 仪表盘四项指标的精确定义与时间范围 | 决定查询 DTO、趋势与同比 | 沿用当前权威四指标，后续服务端补序列和口径元数据 | 标签使用现有“用户总数/有效会员/活动总数/有效报名” |
| 是否新增“普通用户”会员身份 | 会改变领域模型、筛选和权限 | 不新增；用参与历程表达 | 继续用户 + 玩家/嘉宾权益投影 |
| 是否建设手机号/密码/验证码后台账号 | 影响账号安全、供应商、找回与审计 | 继续小程序管理员确认登录 | 仅显示现有账号与会话事实 |
| 是否允许自由配置角色 | 可能扩大权限范围 | 只允许服务端 capability 白名单内策略 | 固定七类角色与 scope 上限 |
| 消息失败是否允许重试 | 影响幂等、收件人快照和审计 | 服务端提供明确重试 action 后再开放 | 只显示失败原因与人工处理入口 |
| 正式支付/退款/权益口径 | 影响金额、订单和会员事实 | 继续以 ledger 与回调为唯一事实 | 浏览器仅显示服务端状态 |

上述问题均不会阻塞 React 展示层、现有 action 的迁移或响应式改造；涉及领域、收费、权益或权限的实现保持关闭，等待明确决策。

## 仍缺少的能力

| 能力 | 缺少原因 | 当前行为 | 推荐后续 |
| --- | --- | --- | --- |
| 玩家增长趋势真实折线 | 现有概览接口没有权威时间序列与口径元数据 | 显示明确空状态，不从总量推导曲线 | 服务端增加带时间范围和口径版本的中立序列 DTO |
| 运营记录举报结案 | 当前列表投影没有稳定 `reportId` 与 `version` | 仅展示服务端记录，不显示不可安全执行的写入口 | 在读模型补齐标识和版本后复用现有写 action |
| 独立密码/验证码账号、自由角色 | 会改变身份与权限模型 | 继续使用小程序管理员确认和 capability 白名单 | 只有业务明确决策并完成安全设计后立项 |
| 其余 7 类素材用途与非空/含敏感字段导出 | 当前生产证据只覆盖 Banner JPEG 和不含手机号的空结果用户导出 | 已验证链路不外推为其他用途、非空数据或手机号能力 | 使用最小权限和隔离测试数据逐项补录，证据不保存导出内容 |
| 正式支付、手机号、扫码签到等真机能力 | 依赖微信真机、商户配置、回调与 ledger | 浏览器只展示服务端事实；开发者工具结果不替代真机 | 在正式配置和授权范围内单独验收 |
| AI/provider 与外部消息投递 | 依赖正式供应商、配额、回执和失败策略 | 只显示服务端实际状态，不伪造成功或自动重试 | provider 明确后验证真实回执、幂等和审计 |
| Mac / Windows 微信客户端 | 最终 runtime 报告证明开发者工具闭环，不代表两个桌面客户端 | 保留兼容性等待项 | 发布前分别记录真实客户端截图和操作结果 |
