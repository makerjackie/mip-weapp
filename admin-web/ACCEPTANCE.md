# MIP 管理后台唯一验收标准

本文件是管理后台产品验收的唯一入口。2026-09-29 按用户要求统一；后续直接修订本文件，不再另建 V0.6、改造版或另一套打勾清单。**这是目标标准，不是已通过验收的声明。** 当前差距见[需求覆盖矩阵](../docs/mip/COVERAGE_MATRIX.md#管理端)，来龙去脉见[本次审查报告](../docs/mip/evidence/admin-audit-20260929/README.md)。

实现顺序、任务和模型交接见 [EXECUTION_PLAN.md](EXECUTION_PLAN.md)。该计划引用本文件，不新增一套验收规则。以下产品场景与第 6 节可维护性条件均属于交付标准。

## 1. 按什么验收

后台要让有权限的运营人员完成“找到对象 → 看懂详情 → 修改允许的内容 → 保存并回读 → 在用户端或流水中确认结果”。页面能打开、接口存在、测试通过，都不单独等于运营可用。

范围包含：概览、用户档案与名片/合作卡/案例、活动、机会、订单、任务、等级/经验/贡献/会籍/勋章、Banner/视频素材、服务器、角色/后台账号/日志、站内消息、笨笨团队。知识等扩展按[产品范围](../docs/mip/REQUIREMENTS.md)保留，不能因隐藏导航就视为取消；已明确下线的 AI 用户入口不因旧原型再恢复。完整后台只在 Web，小程序仅保留现场工作台。

原始资料已固定到[来源快照](../docs/mip/sources/github/20260929-admin/README.md)：

| 输入 | 在本标准中的作用 |
| --- | --- |
| 用户已确认决定、已接受 ADR、现行领域规则 | 决定账号、支付、权限、数据归属及已明确变更；代码现状不能反过来缩减要求 |
| 8 月 25 日 V0.5 评审稿 | 独立用户 Tab、活动整合与预览、机会筛选/导出、已注册管理员、线下奖金等评审要求 |
| 9 月 20 日入库的 v1 PRD/原型 | 补全档案结构、字段、编辑流程和各模块详细范围；内部仍标 V0.4，不能仅凭文件名认定覆盖 V0.5 |
| 本文件 | 将输入合并为可执行场景，冲突明确标出，验收人无需自行猜版本 |

统一解释：保留蓝白后台和原型的信息结构，落实明确要求的功能交互；“仅改侧栏颜色”不能用于阻止修复表单或实现用户独立详情、活动整合。共用组件不意味着所有详情必须用抽屉。日期控件共用，但机会等明确要求区间的列表保留起止时间，不能套用旧“只给开始时间”删掉结束条件。

`S001–S103` 对应 v1 PRD 的 103 个需求块，编号为[提取原文](../docs/mip/sources/github/20260929-admin/requirement-blocks.json)中 `new` 数组顺序。一个块含多项行为，不能拿块数计算完成百分比。下表覆盖全部块；原文用于溯源。业务未决项集中在[产品基线 §16](../docs/mip/REQUIREMENTS.md#16-待业务确认)，相关场景确认前不能通过。

## 2. 所有模块共用的通过条件

| 编号 | 必须验证的行为 |
| --- | --- |
| G01 | 真实登录态、至少一条非空服务端记录；列表、详情、编辑回填字段一致。空列表、demo 和类型检查不能代替。 |
| G02 | 修改普通字段后保存、刷新、重新进入仍保留，未修改字段不丢失；校验失败不写入，取消不保存，冲突保留输入。空回填不能覆盖旧内容。 |
| G03 | 按角色、服务器、对象状态显示操作，服务端再次拒绝越权；账号停用/撤权后旧会话失效。不能靠点击后报错代替正确按钮状态。 |
| G04 | 组合筛选、清除、翻页、返回列表可恢复；排序作用于完整筛选结果。导出匹配筛选、权限和单位，检查非空文件及跨页结果。 |
| G05 | 加载、空态、失败、无权限、保存反馈明确。短暂读失败可有界重试；写入不盲目重发，结果不明先查回；可选统计失败不覆盖成功正文。 |
| G06 | 用户、服务器、角色、标签、素材使用有名字的选项；版本号、技术 ID、内部枚举不作为普通必填项。时间精确到分钟并标明类型，金额用元/万元。 |
| G07 | 1280×720、1440×900、390×844 下长标题、非空表格、全部操作、错误态可用；按钮不挤压标题或被裁切，窄屏重排，键盘可完成主要操作。 |
| G08 | 敏感导出、冻结、权限、发放/冲正、下架/删除记录原因、操作者、时间和对象；版本保护、幂等生效，日志不可编辑，不泄露 OpenID、密码等秘密。 |

## 4. 哪些能改

| 对象 | 修改方式 | 不应提供的捷径 |
| --- | --- | --- |
| 姓名/昵称/简介、公司/职位、组织/职务、职业身份 | 权限内编辑、保留旧值/操作者/版本，档案名片共用数据 | 多页保存互不一致的资料 |
| 头像、城市、行业及其他档案字段 | 完整展示，Q-ADMIN-08 明确逐字段编辑范围 | 将“用户可填”直接等同于“任意运营可改” |
| 手机号、微信绑定、用户 ID | ID 稳定；身份绑定走专门验证/换绑流程 | 普通输入框修改 OpenID 或已验证手机 |
| 玩家身份、到期、经验/贡献、支付状态 | 支付、发放、冲正、退款等业务动作留流水 | 直接改身份、等级、余额和历史交易 |
| 服务器、后台权限 | 独立迁移/授权操作，保留记录、及时撤权 | 编辑名片顺带授权 |
| 活动/机会/任务/合作卡/案例 | 合法状态下完整回填，受保护字段说明原因，保存回读 | 无条件放按钮，提交才失败；未回填就保存 |
| 配置/目录/运营素材 | 新增、编辑、排序、启停，已引用数据保留历史 | 删除造成历史订单/档案/日志损坏 |

## 5. 怎样判定完成

建议按 E → O → U → T/R → A/F → C/M/D/B → X 执行，优先恢复日常运营，不从范围里删除后面的模块。

每条场景记录编号、环境/部署版本、角色/服务器、非敏感样例、步骤、实际结果、截图/回读和未通过原因。原始证据存到 `docs/mip/evidence/<日期>/`；[覆盖矩阵](../docs/mip/COVERAGE_MATRIX.md#管理端)引用编号和结果，不另写规则。

- **通过**：行为、回读、权限和所需跨端结果有证据，相关 G01–G08 同时满足。
- **失败**：已复现缺项、非法入口、回填丢失、布局阻断等不符合项。
- **待验证**：代码存在但未执行完整旅程，历史报告/本地测试不自动等于生产通过。
- **待确认**：来源冲突/业务口径未定，不能打勾或从分母移除。

完整验收要求全部适用产品场景和 K01–K08 通过，未决项经明确决定收口；仍有失败、待验证或待确认时不能称“后台全部完成”。不适用必须有明确的范围决定，不能由执行模型自行排除。阶段交付点名已通过场景和余项；保留非阻断问题也需明确记录阶段交付边界。工程门禁及真机/生产证据层级沿用[全项目验收方法](../docs/mip/ACCEPTANCE.md)，该文档不另定义 Web 产品功能清单。

## 6. 可维护性交付条件

以下条件用于审查本次新增/修改的业务切片及其必要关联路径，不要求为行数或形式重写全部旧代码。功能结果正确但靠复制规则、绕过权限、关闭测试达成时不能通过。

| 编号 | 必须满足 | 可检查的证据 |
| --- | --- | --- |
| K01 单一职责与依赖 | React adapter 只处理展示/交互；领域 module 负责读/编辑模型和校验；服务端决定状态/金额/授权。公共 UI 不认识业务 action，不新建跨小程序页面共享包或万能后台框架。 | diff 中依赖方向清楚，架构检查通过；同一规则没有新增第二个 owner。 |
| K02 数据合同可追溯 | 同一对象只有一份 DTO→编辑→提交转换；真实必需字段缺失明确失败。关键路径不靠宽泛 `any`、强转或空对象回退掩盖合同错误。 | 服务端非空序列化结果通过 module interface 到页面的合同测试；0/false/空数组、旧数据与未修改字段保留用例。 |
| K03 授权与动作一致 | UI 的可用动作来自受控服务端事实，写入仍逐次重验状态与 scope；新岗位模板不能扩大系统角色上限或从一个范围借权到另一范围。 | 状态×角色测试、跨 AppID/服务器、撤权竞态；接口注册不计实现，生产可达功能不得以占位成功返回。 |
| K04 编辑与查询一致 | 编辑冲突保留本地输入，同一对象/账号隔离；列表/排序/分页/导出使用同一查询语义，不以当前页计算总量。 | 两 Tab、迟到响应、冲突与未保存离开；跨页非空查询/导出/下钻一致性。 |
| K05 变更可兼容、可恢复 | 迁移只追加，生成契约可复现，新后端兼容迁移期旧前端；不可变流水不改删，重复/并发不重复发放。配置发布不追溯改写历史。 | migration lock/生成检查、旧记录与幂等测试、目标环境回读、版本和回滚说明；回滚不依赖删业务数据。 |
| K06 测试证明行为 | 在调用方使用的 interface 上测结果；重要失败先有回归样例。mock 使用真实合同结构，单元/React/运行时证据分层。 | 测试会因原缺陷而失败，修复后通过；不只匹配源码字符串，不删失败断言换绿灯，不把 demo/空列表当真实运行。 |
| K07 重构有局部收益 | 随功能抽出真实重复逻辑，旧调用迁移后删除重复实现/死入口；无需知道多个远端文件才能修改一个字段。保留必要兼容 adapter 并说明退出条件。 | diff 能指出复用者和移除的重复代码；没有为减少行数拆成仅转发的 wrapper，没有无关格式化/依赖升级。 |
| K08 可接手、可发布 | 文档只有本标准；计划/checkpoint/状态/证据各司其职。每阶段指明实现、验证、部署和未决边界，密钥及真实敏感数据不进入证据。 | 场景到工作包/代码/测试/运行证据可定位；完整门禁及三个视口结果，目标环境/部署版本/迁移/回滚记录齐全。 |

K01–K08 与对应产品场景一起验收。完整交付须满足全部适用条件；无法验证的项保留待验证，不能用“后续重构”代替必要的正确性、授权或数据保护。
