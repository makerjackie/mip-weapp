# admin-web 交互规范

本规范是 admin-web 管理后台所有页面共同遵守的交互标准。阶段 0 沉淀为共享组件能力，阶段 1 各工作包按此落地。

## 1. 列表筛选 / 搜索 / 排序

### 筛选
- 每个列表页顶部使用统一 `FilterBar`。
- 状态筛选使用下拉选择（Select），不要求手动输入。
- 搜索框支持回车提交和清除按钮，输入不超过 80 字。
- 筛选条件变化后重置分页游标。
- 手机视口下筛选项换行排列，不出现横向溢出。

### 排序
- `DataTable` 支持列点击排序：数值列按大小，文本列按拼音，日期列按时间。
- 排序状态由组件内部管理，不影响 URL（与服务端筛选解耦）。
- 排序图标使用 `@ant-design/icons` 的 `CaretUpOutlined` / `CaretDownOutlined`。
- 默认按服务端返回顺序展示；排序只在当前页数据上做客户端排序。

### 搜索
- 搜索框 `placeholder` 明确提示可搜索的字段范围（如"搜索姓名、手机号或简介"）。
- 搜索与状态筛选可同时生效。

## 2. 表单点选优先规则

- 任何字段如果可选值是有限枚举，必须使用 Select、Radio Group、Checkbox 或 Switch，不要求手动打字。
- 布尔值字段使用 Switch 或 Checkbox，不使用文本输入"是/否"。
- 日期时间字段使用 DatePicker，不要求手动输入日期字符串。
- 多选标签字段使用 `mode="multiple"` 的 Select 或标签点选。
- 纯文本字段（名称、摘要、描述）保持文本输入或 TextArea。

## 3. 表单载体判定标准

按字段数量、嵌套深度和上下文依赖程度分流：

| 维度 | 行内（Inline） | 弹窗（Modal / Drawer） | 独立页面 |
|------|---------------|----------------------|---------|
| 可见字段数 | 1–3 | 4–8 | >8 |
| 嵌套列表 / 动态行 | 无 | 无 | 有 |
| 需对照上下文 | 不需要 | 轻度（抽屉内可见详情） | 需要（需同时看列表或其他记录） |
| 典型场景 | 状态切换、审核通过/拒绝、签到确认 | 简单创建/编辑、退款、归档原因 | 活动编辑、机会创建、任务创建分配、知识内容编辑 |

### 判定结论清单

详见 [FORM_AUDIT.md](./FORM_AUDIT.md)。

### 独立页面路由约定
- 复杂表单使用 `/events/new`、`/events/:eventId/edit`、`/opportunities/new`、`/tasks/new` 等路由。
- 独立页面保留面包屑返回列表，提交后回到列表并显示成功反馈。
- 独立页面内的字段同样遵守点选优先规则。

## 4. 加载 / 成功 / 失败反馈

### 加载态
- 页面首次加载：`LoadingState`（Skeleton）。
- 表格刷新：表格区域显示 `Spin` 遮罩或行级 Skeleton。
- 按钮提交：按钮 `loading` 禁用，防止重复提交。
- 行内操作：操作按钮 `loading`，同一行其他操作禁用。

### 成功反馈
- 写操作成功：`message.success`，文案为"操作名称+已提交"（如"保存活动已提交"）。
- 批量操作成功：`message.success`，文案包含处理数量（如"已批量审核 3 条报名"）。
- 成功后自动刷新列表（invalidateQueries）。

### 失败反馈
- 写操作失败：表单内 `Alert` 显示错误，文案使用人能理解的语言。
- 网络错误：`message.error` + ErrorState 重试按钮。
- 权限不足：`message.error("当前账号没有执行此操作的权限")`。
- 版本冲突：保留填写内容，提示"记录已更新，请核对后重新提交"。
- 错误文案规则：不展示原始错误码；将常见错误码映射为中文说明（如 `VERSION_CONFLICT` → "记录已被其他人更新，请刷新后重试"）。

## 5. 批量操作

- `DataTable` 支持行选择（Checkbox 列）。
- 选择后底部出现批量操作栏，展示已选数量和可用操作按钮。
- 批量操作需二次确认（ConfirmDialog），确认后显示 loading。
- 批量操作完成后自动清除选择并刷新列表。
- 批量操作适用场景：报名审核、内容审核、公告发布/下架、任务成员分配。
- 不适用批量操作的场景：涉及金额、退款的操作。

## 6. 确认弹窗

- 危险操作（删除、归档、下架、退款）必须弹 ConfirmDialog。
- 确认弹窗标题 = 操作名称；描述说明后果和服务端校验。
- 危险操作按钮使用 `danger` 样式。
- 确认弹窗在提交期间不可关闭（mask closable = false）。

## 7. 抽屉内完成操作的模式

- 详情通过 `DetailDrawer` 展示，不跳页。
- 抽屉内可发起操作（审核、签到、状态变更等），操作通过 `MutationDialog` 在抽屉之上弹出。
- 抽屉内的操作完成后自动刷新详情数据。
- 简单操作（如签到确认、审核通过）可使用抽屉 footer 的快捷按钮，一步完成。
- 复杂操作（需多字段填写）仍使用 MutationDialog，但遵守表单载体判定标准。

## 8. 手机视口适配

- 390px 必须真正重排：筛选项垂直排列、表格横向滚动、抽屉全宽。
- 不保留造成横向溢出的桌面侧栏。
- 表格操作列在手机视口下使用 `fixed: 'right'` 并限制宽度。
- 弹窗在手机视口下使用 `width: '100%'`。

## 9. 一致性要求

- 同一交互在所有页面表现一致：筛选、搜索、排序、操作反馈、确认弹窗的样式和行为不因页面不同而变样。
- 新页面必须使用共享组件（FilterBar、DataTable、MutationDialog、ConfirmDialog 等），不自行实现等价组件。
- 状态标签统一使用 `StatusTag`，不自行硬编码 Tag 颜色。
