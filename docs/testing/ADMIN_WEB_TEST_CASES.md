## 2. 通用约定

- 视口：桌面优先；视觉相关变更必须验收 **1280×720、1440×900、390×844** 三个视口；390px 必须真正重排（筛选竖排、表格横向滚动、抽屉全宽、弹窗 100% 宽）。
- 通用通过条件引用 ACCEPTANCE.md G01–G08：真实登录态与非空数据（G01）、保存回读一致（G02）、按角色/范围出操作且服务端拒绝越权（G03）、筛选翻页导出一致（G04）、五态反馈（G05）、人类可读选项与单位（G06）、三视口可用（G07）、敏感操作留痕不泄露（G08）。
- Mutation 运行时：所有写操作带顶层幂等键（`web-<action>-<uuid>`）与服务端 `expectedVersion`；CONFLICT 保留输入提示「记录已被其他人更新…」；FORBIDDEN 提示无权限；AUTH_REQUIRED 清会话弹登录框。
- 服务端事实边界（违反即 Bug）：页面不能决定金额、退款金额/状态、会员时长、报名资格、管理员角色；详情不完整时不得伪造版本；生产登录/上传/导出/支付/CloudBase 的成功事实须单独标注证据边界。
- 金额展示用元/万元、时间到分钟并标注类型、必填选项使用有名字的选项（G06）。
- 演示模式 `VITE_MIP_ADMIN_DEMO_MODE=true` 时持续显示「演示数据」标识，不能登录/改密/提交写操作；真实请求失败不得回退演示数据。

## 19. 验收执行顺序与门禁

- 建议顺序（ACCEPTANCE.md）：活动 E → 机会 O → 用户 U → 任务/成长 T/R → 账号/订单 A/F → Banner/消息/概览/团队 C/M/D/B → 扩展 X。

- 门禁命令：仓库根目录 `pnpm admin:web:verify`；全量 `pnpm verify:all`。生产登录/上传/导出/支付/CloudBase 的成功事实必须单独标注证据边界（本地测试 ≠ 生产通过）。
