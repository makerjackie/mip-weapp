## 2. 通用约定

- 优先级：P0 = 主流程冒烟（必测）；P1 = 核心分支；P2 = 边界与体验。
- 标记 **[真机]** 的用例必须微信真机验证，开发者工具结果不作数：手机号绑定、支付、订阅消息、扫码签到、相册保存。
- 服务端事实边界（贯穿所有用例，违反即 Bug）：客户端不决定价格与会员时长、报名资格与库存、支付是否成功、公开资料可见性、管理员角色；页面只提交意图（`planId`/`orderId`/报名答案等），不提交金额、商户单号或权益天数。
- 受保护动作门禁：进入需身份完整性的动作（`ENTER_APP`、`REGISTER_EVENT`、`PURCHASE_MEMBERSHIP`、`PUBLISH_OPPORTUNITY`、`INTERACT`、`VIEW_RESTRICTED_PROFILE`、`ENTER_ADMIN`、`EDIT_PROFILE`）时，按 `AUTHENTICATED → AGREEMENTS → PHONE → PROFILE` 顺序逐步补全（`mip-access` 页），补全后回到原意图继续。身份失败后的重试必须重新确认身份，不能复用旧判定。
- 通用页面状态验收：每个数据页检查 loading / empty / error / forbidden / conflict 五态文案与「重新加载」行为；错误不得让已成功的正文整页消失（装饰性请求失败不影响正文）。
- 表格列「角色」为该用例的主执行角色；标注多角色时逐一验证。

## 13. 上线门禁

- 上传体验版/正式版前必须通过完整 `pnpm verify:all`（含 `pnpm verify`、`pnpm admin:web:verify`）。
