# ADR 0001：付费活动使用名额保留，并由支付 ledger 创建报名

- 状态：已采用
- 日期：2026-07-25

## 背景

会员案例已经有微信支付 ledger、活动容量锁和免费报名。如果在调起支付前直接创建报名，未付款用户会长期占用名单；如果支付回调只修改订单而不处理席位，订单和报名会产生两个不一致的真相。

## 决策

付费活动提交报名时先在活动事务内创建短时名额保留和 `EVENT` 订单。客户端只拿到订单 ID 并调起现有微信支付适配器。

支付回调或权威查单必须进入现有 payment ledger。在同一数据库事务内：

1. 校验订单所有权、金额、币种和交易状态；
2. 将订单标记为 `PAID`；
3. 将对应名额保留转换为正式报名；
4. 写入审计记录。

取消付费报名时创建全额退款请求。退款终态由回调或权威查询确认；确认后再把报名收敛为已取消。

## 后果

- 页面不需要了解库存、订单、回调和报名转换顺序。
- 未付款订单不会伪装成正式报名。
- 需要保留一个可过期的 Reservation 概念，并在容量计算中纳入受保护的支付中名额。
- 支付后报名创建失败必须整体回滚，让支付回调重试，而不是承认一个没有席位的成功支付。
- 首版不支持部分退款、多票种和多人票，以控制 ledger 状态空间。
