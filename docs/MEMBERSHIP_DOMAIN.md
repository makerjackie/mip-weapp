# Membership domain

用户端与运营端共享同一套服务端事实。客户端不能决定：

- 价格与会员时长
- 报名资格与库存
- 支付是否成功
- 公开资料可见性
- 管理员角色

## 边界

| 域 | 客户端 | 服务端 |
| --- | --- | --- |
| 身份 | 触发手机号授权 | `FROM_OPENID \|\| OPENID`、换票 |
| 会员 | 选择 planId | 方案目录、权益重算 |
| 活动 | 提交报名答案、相册素材引用与撤回意图 | 乐观锁、票码、取消收敛、参与资格和相册发布状态 |
| 社区 | 关注/屏蔽/举报入口 | 不通知被屏蔽者；举报不自动处罚 |
| 机会评论 | 评论、项目评价、打 call 和举报意图 | 内容安全、参与人标识、审核状态、幂等关系和计数 |
| 机会撮合 | 选择本人已发布机会、查看解释、提交反馈与偏好 | 候选范围、公开字段、屏蔽过滤、分数、阈值、结果版本和通知 |
| 知识内容 | 搜索筛选、阅读、评论和提交购买意图 | 发布状态、受保护交付信息、价格、解锁权益、首次访问和退款资格 |
| 任务 | 查看本人当前分配且符合当前成长等级的任务、下载模板、提交任务和本人拥有的图片素材引用 | 发布窗口、全员或指定成员派发、成长等级精确允许集合、附件要求、单次完成和经验值奖励；列表与完成动作都按服务端当前经验重新判级 |
| 勋章 | 查看本人收藏、选择最多 3 枚佩戴 | 目录状态、获授/撤销事实、佩戴槽位和版本冲突 |
| 后台 | 展示 capability | RBAC |

新建会员购买订单和调用管理 API 前，服务端必须按当前 AppID 重新确认用户为 `ACTIVE`，已接受当前版本协议，已绑定手机号，且资料已包含昵称和主分会。管理角色和 capability 在这些事实之后校验。已有订单查询、同一幂等购买请求恢复和退款恢复不因协议换版或资料状态变化被阻断，但仍必须通过可信微信身份和 AppID 校验订单归属。

玩家成长页的“邀请加入”只使用 `mip-commerce-api` 生成的会员邀请 token；“立即续费”进入统一会员方案页，由既有 checkout、支付和 ledger 链路处理，不在成长页复制支付判断。

改表必须追加 `database/mysql` 迁移。支付逻辑变更必须同步 ledger 测试。真机验证清单见 [RUNTIME_ACCEPTANCE.md](RUNTIME_ACCEPTANCE.md)。

知识内容、采集、单内容订单、权益、退款与通用评论合同见 [KNOWLEDGE_CONTENT.md](KNOWLEDGE_CONTENT.md)。

档案中的嘉宾、互动、感兴趣和访客聚合、列表及隐私口径见 [PROFILE_INFLUENCE.md](PROFILE_INFLUENCE.md)。

举报、屏蔽、公开列表过滤和解除屏蔽合同见 [COMMUNITY_SAFETY.md](COMMUNITY_SAFETY.md)。

机会评论和项目评价要求当前身份通过协议、手机号和资料门禁。项目评价只在机会结束后开放；“参与人”只从发布人或机会团队历史关系推导，客户端不能自行标记。只有机会发布人或当前有效团队成员可以打 call；评论编辑窗口、软删除、打 call 计数、审核状态和举报事实均由服务端维护。

机会撮合只接受本人拥有或参与的已发布机会，管理重算则要求当前机会范围内的 `opportunities.moderate` capability；管理端发送前和机会服务接收后都根据当前角色与机会范围重新授权。服务端按来源机会版本、合作角色、行业、能力、城市分会或城市范围生成结果，并在最终写入事务锁定来源机会、用户状态、通知/撮合偏好和范围阈值版本。列表读取再次复核候选仍有效、项目仍发布、资料字段仍公开且双方未屏蔽；未公开的主分会不参与人才范围匹配，也不出现在解释中。客户端和外部 provider 只使用请求范围内的签名 `candidateRef`，人才用户 ID 和分会、城市、标签内部主键不出服务端。撮合请求、结果版本和反馈保留历史，不因重新计算物理覆盖。用户偏好使用乐观版本和幂等键保存，后台阈值设置使用范围授权、乐观版本和追加审计。

账号注销的未结交易阻塞、撤销与保留表清单、身份墓碑和不可逆 rollback 边界见 [ACCOUNT_CLOSURE.md](ACCOUNT_CLOSURE.md)。

活动相册只接受当前活动 `REGISTERED` / `ATTENDED` 参与者提交。客户端先压缩图片，但 `mip-media-api` 仍负责完整解码、重编码和图片内容安全；`mip-events-api` 再按 AppID、owner、`READY` 和 `EVENT_ALBUM` purpose 复核素材，并根据活动的 `AUTO` / `REVIEW` 配置决定发布或待审。本人撤回与运营审核均使用版本校验并保留事实和审计，不物理删除照片记录。

活动报名、修改报名、候补晋升和审核通过均重新核对当前参与资格；修改和晋升不得绕过当前协议、手机号、资料及活动要求的会员权益。候补活动需要审核时，晋升进入待审核。我的活动保留待参加、已参加（已签到）和历史三个分类；历史包括已取消、未通过，以及未签到但已结束或活动已关闭的报名，分类和计数由服务端返回。

付费报名的占位过期后，重新报名在当前资格、报名窗口和容量允许时续期原订单占位，不替换原订单金额。未支付报名可取消，不受正式报名取消截止限制。已取消重报后旧订单迟到支付创建独立退款和审计；退款提交及成功回调核对原订单和失效占位，不修改新报名。
