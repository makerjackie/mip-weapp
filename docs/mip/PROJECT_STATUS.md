## 定向重构范围

不做整体重写，只继续处理会阻碍并行或维护的深模块问题：

1. 保持现有渠道中立管理合同稳定；Web 只增加 principal/transport，不复制业务规则。
2. 将 `mip-admin-api` 过大的 repository 按用户、活动、订单、权限、消息和知识逐域抽成内部深模块，保留一个部署单元和 187 个公开 action。
3. 页面继续只经过 modules 与 platform；不在页面复制资格、金额、权限和状态机。
4. 审核未注册页面和旧模块时先证明无有效入口，再做删除，避免用清理制造回归。
5. 持续区分 `implemented-local`、`external-wait`、运行证据和生产证据，禁止用文件或测试数量冒充产品完成。
