# MIP 小版本交付路线

当前采用“先验证底座和一条真实闭环，再并行扩展”的方式。当前目标是完整小程序和手机/电脑双端自适应管理分包；独立网页后台暂不建设。小版本只用于控制风险和获得真实反馈，不用于永久裁剪业务需求。

## 为什么不立即全量并行

当前最大风险不是页面数量，而是以下共享事实还没有被两端共同验证：

- 同一个用户和管理员身份；
- 平台、城市分会和活动三级权限；
- 手机与电脑布局共享 action、DTO、错误和审计；
- 真实测试数据和可重复夹具；
- 媒体、支付、消息和原生微信能力的外部边界。

如果这些 seam 没有先固定，多 Agent 会分别创建身份、权限、分页、错误和状态处理，后续合并成本很高。

## 检查点 A：管理底座

目标是先固定可供小程序两种尺寸和未来 Web 共用的服务端契约，再开展页面并行开发。

1. 固定现有管理 action manifest、输入输出、错误和审计 envelope。
2. 建立 `AdminTransport`，当前实现 CloudBase 和 InMemory，未来可以增加 HTTP。
3. 建立 `AdminApplication.execute(trustedPrincipal, command)` 和统一 operation registry。
4. 将 `mip-admin-api` 按权限、用户、订单、消息、知识、活动等内部深模块逐步拆分，保留一个部署单元。
5. 建立会员端居中容器、管理端宽屏容器和三档响应式原语。
6. 用用户管理和免费线下活动验证查询、编辑、版本冲突、审计、范围权限与手机/电脑一致性。

该检查点不依赖支付、媒体上传或外部消息投递。通过后，管理合同和响应式壳层才可以成为后续并行开发的稳定底座。

## 小版本 V0.1：免费活动闭环

这是第一个交给业务方真实测试的产品版本：

1. 管理员在微信电脑端选择授权城市分会。
2. 管理员创建、预览、编辑并发布一场免费线下活动。
3. 小程序按城市浏览、搜索并查看活动详情。
4. 嘉宾完成协议、档案和免费报名，进入“我的活动”。
5. 微信电脑端查看参与名单、报名状态和审计。
6. 微信电脑端展示或导出签到码；手机小程序完成扫码签到。
7. 用户在手机完成心动和活动反馈；电脑端查看相应运营数据。
8. 仪表盘展示这条闭环产生的真实指标和待办。

首版不接真实支付，避免把商户配置、回调和退款问题与网页登录、分会权限、活动状态机同时混在一起。

## V0.1 验收门槛

- 使用可重复的 Owner、城市管理员、玩家和嘉宾测试身份。
- 使用明确的分会、活动、报名和签到夹具；不得写入其他项目表。
- 平台管理员能跨分会，城市管理员只能访问授权分会，现场工作人员只能访问指定活动。
- 手机和电脑端看到相同活动、报名和状态版本。
- 页面覆盖 loading、empty、error、forbidden、conflict 和 disabled。
- 微信开发者工具、Windows 微信和 Mac 微信都有真实运行截图。
- 手机号和扫码按真机边界单独记录，不用模拟结果冒充真机通过。
- `pnpm verify`、响应式运行验收、服务端合同测试和 `git diff --check` 通过。

## V0.1 反馈后再并行

底座和免费活动闭环通过后，可以按以下相对独立的纵向切片并行：

| 切片 | 主要范围 | 共享依赖 |
| --- | --- | --- |
| 支付与会员 | 会员方案、付费活动、订单、回调、退款、权益 | ledger、正式商户、真机 |
| 用户与档案 | 用户管理、档案、合作卡、超级案例、勋章 | 身份、媒体、隐私 |
| 机会与撮合 | 机会、团队、引荐、评论、评价、AI 撮合 | 用户可见性、消息 |
| 成长与任务 | 等级、经验、贡献、任务、模板、完成审批 | 成长流水、媒体 |
| 游戏化 | 赛季、队伍、排行、盲盒和游戏币 | 有效会员、成长账户 |
| 知识与内容 | 来源、分类、内容、评论、单内容付费 | 媒体、订单、网页域名 |
| 消息与运营 | Banner、视频回顾、消息模板、活动和发送记录 | outbox、跳转白名单 |
| 系统管理 | 角色、后台账号、分会、审计和安全 | trusted principal、RBAC |

每个 Agent 只拥有一个纵向切片；身份、订单、权限、分页、错误、审计 envelope 和跨域事件名由底座统一维护。

## 暂不做的事情

- 不推倒重写现有小程序或 Cloud Functions。
- 不立即删除小程序管理分包。
- 不在任一页面复制服务端资格、金额、权限和状态机。
- 不在真实桌面试用证明需要前建设独立 Web UI、网页登录和 Session。
- 不把 WorkBuddy 原型的“普通用户”“服务器”“一年会籍”等冲突规则直接写入数据库。
- 不在测试身份和业务夹具未准备好时用空页面截图宣布完成。
