2. 用户管理

需求点需求描述
用户角色
  • 角色分为：普通用户、嘉宾、玩家
  • 系统记录当前角色及角色变更记录
角色流转
  • 普通用户 → 嘉宾：用户参与过“早会”类型活动后自动成为嘉宾
  • 普通用户/嘉宾 → 玩家：用户成功缴纳会费后自动成为玩家
  • 玩家 → 嘉宾：玩家权益到期后自动成为嘉宾
  • 用户角色不支持在用户管理后台手动修改
玩家权益周期
  • 玩家权益固定有效期为 1 年
  • 玩家加入时间：记录用户首次成功缴纳会费并成为玩家的时间
  • 用户加入时间：记录用户首次建立 MIP 用户账号的时间
  • 权益到期时间：按玩家加入日期计算为次年同月同日
权益到期处理
  • 玩家权益到期后，系统自动将角色改为嘉宾
  • 记录原角色、变更后角色、变更时间和变更原因
  • 续费成功后，按新的缴费时间重新计算 1 年权益周期
用户列表字段
  • 头像：展示当前用户所使用的头像
  • 昵称：展示用户当前所使用的昵称
  • 手机号：手机号需脱敏展示
  • 当前角色：展示当前角色，包括普通用户、嘉宾或玩家
  • 行业：展示用户当前行业
  • 当前身份：展示用户当前身份状态
  • 用户等级：仅展示 Lv. 级别数字，如“Lv.8”
  • 贡献值：以 K 为单位展示用户当前累计贡献值，如“3.28K”
  • 玩家权益状态：玩家展示生效中、本月到期、下个月到期或已到期未续费；普通用户和嘉宾展示“—”
  • 用户注册时间：展示用户首次建立 MIP 用户账号的时间
  • 玩家到期时间：展示当前玩家权益周期的到期日期
用户列表规则
  • 默认展示当前后台账号所属服务器的数据
  • 支持按服务器切换筛选；跨服务器查看需具备对应数据权限
  • 搜索：支持根据用户 ID、昵称、手机号或关键词搜索出用户；系统支持模糊搜索，关键词包含用户档案相关的关键词
  • 支持根据用户选择的行业筛选列表数据
  • 支持根据用户选择的当前身份筛选列表数据
  • 玩家权益状态筛选：支持选择生效中、本月到期、下个月到期或已到期未续费
  • 时间筛选：复用机会管理的自定义日期时间组件，先选择时间类型，再填写日期和时刻，支持按用户注册时间或玩家到期时间筛选
  • 时间筛选仅匹配所选时间字段，不混用用户注册时间和玩家到期时间
  • 导出：支持导出当前筛选结果
用户城市与服务器归属
  • 普通用户和嘉宾不绑定服务器，服务器字段展示为空
  • 只有玩家拥有当前所属服务器
  • 所有用户均可记录当前城市，当前城市与服务器为两个独立字段
  • 用户列表支持展示当前城市标签
  • 玩家成为玩家后，根据业务规则建立服务器归属并记录变更时间
用户档案左侧-数据看板
  • 展示位置与结构：位于用户档案左侧，顶部展示头像、昵称、用户身份与账号状态；下方展示“社交影响力数据”卡片，右上角固定标识“当前累计”。数据卡片按两列排列，共展示 8 项指标。
  • 头像：展示当前用户所使用的头像；无头像时展示默认头像。
  • 昵称：展示用户当前所使用的昵称；无昵称时展示“未设置昵称”。
  • 用户身份：展示当前用户身份，包括普通用户、嘉宾或玩家。
  • 账号状态：展示账号当前状态，枚举为正常、已冻结；正常显示绿色状态标签，已冻结显示冻结状态标签。
  • 统计口径：全部指标均按当前用户维度累计展示，不限定时间范围；统计数据刷新时同步更新看板数值。
  • 邀请嘉宾数（invite_guest_count）：展示该用户成功邀请参加活动的嘉宾去重人数，单位为“人”。
  • 互动用户数（interactive_user_count）：展示与该用户产生有效互动的去重用户人数，单位为“人”。
  • 我的心动数（my_like_count）：展示该用户主动向其他用户发起心动的累计次数，单位为“次”。
  • 对我心动数（received_like_count）：展示其他用户向该用户发起心动的累计次数，单位为“次”。
  • 主页访客（profile_visit_count / profile_visitor_count）：同一卡片展示主页访问总次数与去重访客人数，格式为“{profile_visit_count} 次 / {profile_visitor_count} 人”。
  • 活动参与（event_registration_count / event_checkin_count）：同一卡片展示活动报名次数与签到次数，格式为“报名 {event_registration_count} / 签到 {event_checkin_count}”。
  • 发布数（publish_count）：展示该用户累计发布的机会数量，单位为“个”。
  • 想引荐数（referral_intent_count）：展示该用户累计发起“想引荐”的次数，单位为“次”。
  • 空数据：单项无数据时显示 0，并保留对应单位；数据加载失败时该项显示“—”，不以 0 替代。
  • 影响力数据仅在左侧数据看板展示一次，不在右侧详情标签中重复展示。
玩家档案－基础信息
  • 用户 ID：展示系统分配的唯一用户账号标识
  • 手机号：手机号需脱敏展示
  • 绑定微信：展示当前账号绑定的微信号
  • 用户身份：展示用户当前为普通用户、嘉宾或玩家
  • 所属服务器：展示用户当前归属的服务器/分会
  • 用户注册时间：展示用户首次建立 MIP 用户账号的时间，格式为 YYYY-MM-DD HH:mm，精确到分钟
  • 玩家加入时间：展示用户首次成功缴纳会费并成为玩家的时间，格式为 YYYY-MM-DD HH:mm，精确到分钟
玩家档案－成长信息
  • 加入 MIP 年限：展示根据首次加入时间计算的玩家年限
  • 玩家到期时间：展示当前玩家权益周期的到期日期，格式为 YYYY-MM-DD
  • 当前等级：展示用户当前成长等级
  • 累计经验值：展示用户当前累计获得的经验值
  • 贡献值：展示用户当前累计贡献值
  • 当前拥有徽章：展示该玩家已获得且当前有效的徽章名称、图标、获得时间和状态
  • 徽章发放：在“当前拥有徽章”区域提供徽章编辑器，支持从已启用的徽章中多选；管理员选择后必须点击“保存确认”才为该用户添加所选徽章
  • 未保存时切换页面或标签不写入变更；保存成功后更新当前拥有徽章，并提示“徽章已保存”
  • 已拥有的徽章在编辑器中默认选中，重复选择不重复发放
玩家档案－职业信息
  • 所属城市：展示用户当前所在城市
  • 行业：展示用户所属行业分类
  • 职业角色：展示用户当前职业身份
  • 公司：展示用户当前所在公司
  • 职位：展示用户当前职位
  • 一句话介绍：展示用户填写的个人简介
玩家档案－邀请嘉宾
  • 嘉宾昵称：展示该玩家邀请的嘉宾昵称
  • 嘉宾 ID：展示被邀请嘉宾的用户 ID，支持点击进入用户详情
  • 当前角色：展示被邀请嘉宾当前的普通用户、嘉宾或玩家角色
  • 展示该玩家曾经邀请过的全部嘉宾名单
  • 点击嘉宾记录打开对应用户详情
  • 嘉宾账号停用后保留邀请记录，昵称和 ID 按权限展示
玩家档案－心动关系
  • 关系方向：展示我心动的人、对我心动的人或双向心动
  • 关联用户：展示对方头像、昵称及按权限展示的用户标识
  • 关联活动：展示产生心动关系的活动名称
  • 发生时间：展示心动关系首次建立的时间
  • 关系状态：展示有效、已撤销或已失效
  • 最近更新时间：展示关系状态最近一次变化时间
  • 支持按关系方向、活动、状态和时间筛选
  • 点击关联用户进入对方用户档案，点击活动进入活动详情
  • 已撤销或已失效关系仅保留后台历史记录，前台不再展示
  • 无权限查看敏感信息时仅展示头像和昵称
名片管理
  • 名片字段：姓名、头像、公司、职位、联系方式和 MIP 身份
  • 模板字段：模板名称、样式预览、必填项、排序和状态
  • 支持查看用户名片及配置可用模板
  • 支持启用、停用和排序模板
  • 支持下架违规名片并填写原因
  • 保留用户名片修改记录和历史版本
合作卡管理
  • 合作卡固定分为 6 种：皮条客、生意佬、暴发户、狗策划、死美工、老保姆；每种卡型的说明、特征评分项和菜单字段按对应卡型配置，不使用“卡型 5 / 卡型 6”等占位名称
  • 简写：每张卡展示卡型、我的目标、需要引荐三项核心内容；点击“查看详情”展开当前卡片，不跳转离开用户档案
  • 共同详情字段：姓名/游戏名、卡型说明、特征打分、目标、需要的支持或引荐的是、臭毛病（外显）、病因（内在）、预防发作建议（行为）、和我合作最大的价值是
  • “需要被理解的臭毛病”作为外显、内在和预防建议的分组标题，不单独生成重复字段
  • 皮条客详情：特征评分为开拓人脉、引荐人脉、长期维护、引荐商机、卖点提炼、跨圈交际；展示常混迹的圈子，并支持填写圈子名称、圈内身份、圈内年限、圈子特点简述
  • 生意佬详情：特征评分为商机洞察、财务测算、盈利建模、资源整合、利益统筹、合作谈判；本人的菜单字段为做过行业或在做行业、行业年限、卖点
  • 暴发户详情：特征评分为投资洞察、上市规划、股权规划、投融策划、融资达成、资源整合；本人的菜单字段为擅长领域、领域年限、成就
  • 狗策划详情：特征评分为项目调研、项目定位、创新创意、方法设计、提案竞标、落地规划；本人的菜单字段为类型、擅长领域、卖点
  • 死美工详情：特征评分为视觉策略、视觉设计、素材搜寻、视觉落地、视觉管理、提案竞标；本人的菜单字段为类型、擅长领域、卖点
  • 老保姆详情：特征评分为目标计划、执行统筹、进度复盘、沟通机制、标准研发、应急沟通；本人的菜单字段为类型、擅长领域、卖点
  • 字段格式：6 项特征评分使用 1 至 5 星；目标、引荐需求、菜单说明、合作价值、外显表现、内在原因和预防建议使用多行文本
  • 支持先查看详情，再点击“编辑”修改；点击“保存”后保存当前卡片的全部变更并展示保存成功提示。保存记录修改人、修改时间和变更内容
  • 卡片支持按卡型切换，停用后不在前台展示但保留后台历史
超级案例管理
  • 一个用户可维护多个超级案例，案例按开始时间倒序展示
  • 详情字段：案例封面、项目名称、一句话描述案例、开始时间、担任职责、主营城市、主营地区、项目类型、展开讲讲
  • 展示规则：每个案例独立展示封面和全部详情字段；“展开讲讲”为全文内容，不截断为单行摘要
  • 后台支持对单个案例手动编辑和保存；点击“编辑”后仅开放当前案例字段，点击“保存”后记录修改人、修改时间和内容版本
  • 支持异常下架，公开且未下架的案例进入用户主页和人才搜索
用户档案－操作记录
  • 用户详情页提供“操作记录”标签，按时间倒序展示该用户相关操作
  • 记录字段：操作内容、操作类型、时间、操作人
  • 操作类型：按实际业务动作记录，例如查看、编辑、冻结、解冻、发放徽章、保存合作卡和保存超级案例
  • 操作人：记录执行操作的后台账号或小程序用户，并展示其名称及来源类型
  • 时间精确到分钟；记录创建后不可由普通用户修改或删除
  • 无记录时展示“暂无操作记录”

3. 活动管理

需求点需求描述
活动列表金额调整
  • 活动金额：列表原“费用类型”字段改为活动金额；免费活动显示 0，付费活动显示 199、299 等实际金额
  • 金额筛选：列表原“费用筛选”改为按活动金额筛选
  • 活动设置入口：活动列表页顶部“导出”改为“设置”，点击进入活动设置页
活动标签设置
  • 标签字段：展示标签名称和状态
  • 新增标签：支持输入新标签名称并设置初始状态
  • 编辑标签：支持修改标签名称，标签名称不可重复
  • 状态管理：支持启用和停用；停用后不影响历史活动已有标签数据
  • 表单联动：创建和编辑活动时仅可多选当前已启用的活动标签
  • 操作记录：保存新增、编辑、启用和停用操作的操作人和操作时间
活动列表字段与筛选
  • 列表字段
    • 活动名称：展示活动标题，限制 20 个字符以内
    • 活动标签：展示后台配置的活动分类标签
    • 费用金额：展示活动实际金额，免费活动显示 0，付费活动显示 199、299 等具体金额
    • 开始时间：展示活动开始日期和时间
    • 结束时间：展示活动结束日期和时间
    • 所属服务器：展示服务器对应的城市名称
    • 报名人数：展示当前已报名人数
    • 活动状态：展示已发布、已结束或已取消
    • 创建时间：展示活动创建时间
  • 列表筛选
    • 开始时间筛选：使用全局方案 B 开始时间组件，日期精确到年月日、时间精确到分钟，不筛选结束时间
    • 费用金额筛选：按活动金额筛选
    • 活动标签筛选：可选择后台已配置且已启用的活动标签
    • 服务器（城市）筛选：可按服务器对应的城市筛选
活动状态
  • 已发布：完成预览确认后发布，活动在小程序正常展示
  • 已结束：活动结束时间到达后系统自动流转，保留活动详情、参与人和历史数据
  • 已取消：管理员取消活动后停止前台展示和新报名，保留历史记录
  • 草稿仅为创建过程中的临时编辑记录，不作为活动列表状态
创建与编辑活动
  • 基础信息
    • 配置活动名称、封面、活动标签、费用类型、金额、场地、日期、时间和报名须知
    • 费用金额联动：选择免费时金额固定为 0 且不可填写；选择付费时开放金额输入且必须填写大于 0 的金额
    • 场地地址文案：支持手动填写活动场地名称或地址
    • 场地跳转链接：支持手动填写可跳转的场地链接，可为空；填写时校验为有效的 https:// 地址
    • 活动日期支持单日或持续日期
  • 图文内容
    • 活动介绍和主办方介绍使用文字编辑器
    • 支持图文输入、文字排版和图片上传
  • 预览与发布
    • 编辑完成后支持按小程序展示效果预览
    • 预览确认后才可发布活动
    • 不设置审批流程
  • 草稿恢复
    • 创建过程中退出且未发布时自动保留临时编辑记录
    • 再次进入创建页时支持继续编辑该草稿
    • 草稿不进入活动列表，不对前台展示
手机端活动预览
  • 创建或编辑活动时点击“预览”，以手机尺寸弹层展示小程序活动详情页
  • 预览需展示封面、标签、活动名称、开始与结束时间、场地文案、费用金额、参与人、活动介绍、主办方介绍、报名须知和报名按钮
  • 图文内容按照手机端实际宽度和排版效果展示
  • 预览仅用于检查展示效果，不产生报名、支付或发布数据
  • 支持关闭预览并返回当前编辑内容
活动列表排序
  • 活动列表默认按照活动开始时间排序
  • 开始时间越早的活动越靠前展示
复制历史活动
  • 支持在活动列表复制已有活动
  • 复制后进入新的活动编辑草稿
  • 活动标题、开始日期、开始时间、结束日期和结束时间不复制，必须重新填写
  • 补全必填字段并完成预览确认后方可发布
参与人列表
  • 活动详情展示全部参与人

  • 支持手机号和密码登录

  • 账号停用后两种登录方式均不可使用
新增与编辑账号
  • 表单字段包括姓名、登录账号、手机号、角色、服务器归属、最后登录时间和登录记录
  • 创建与编辑表单不展示登录方式、账号状态和审计日志字段
  • 表单校验
    • 姓名或登录账号为空时提示请填写完整账号信息
    • 手机号格式不正确时提示请输入正确的手机号
    • 登录账号或手机号重复时提示登录账号或手机号已存在
    • 未选择角色或服务器归属时提示请选择角色和服务器归属
    • 校验失败时不可保存，不覆盖原账号信息
  • 支持修改姓名、手机号、角色和服务器归属
  • 修改登录账号、角色或服务器归属时记录操作日志
账号创建流程
管理员进入后台账号管理→填写账号信息→校验手机号与账号唯一性→分配角色和服务器权限→创建成功并通知账号本人
  • 创建人必须具备后台账号新增权限
  • 校验失败时停留在表单页并提示具体原因
  • 创建成功后生成账号记录并记录创建人、时间和权限快照
  • 账号本人使用手机号验证码或手机号密码登录

  • 停用后立即禁止登录，不删除历史操作记录
  • 当前登录账号不可停用自身
  • 最后一个超级管理员账号不可停用或降权
  • 账号不做物理删除
NPC／笨笨后台身份
  • NPC／笨笨作为后台账号角色，不作为小程序用户角色
  • 可按权限执行任务派发、任务验收和相关用户查询
  • 账号绑定可管理服务器和业务范围
  • 无权限时不可查看其他服务器数据或敏感信息

  • 字段：登录账号、登录时间、登录结果、IP 地址、设备信息和失败原因
  • 支持按账号、结果和时间筛选
  • 连续登录失败的限制规则待确认
审计日志

  • 记录机会状态修改、经验值和贡献值处理、任务派发和验收
  • 记录勋章发放撤销、订单退款和消息发送
  • 字段：操作者、角色、服务器、模块、操作类型、业务对象、变更前后内容、时间和原因

  • 不得造成用户经验值小于 0

8. 权益管理

需求点需求描述
权益流水
  • 权益管理汇总展示经验值、贡献值和玩家会籍的发放流水，不替代原经验值、贡献值和订单模块
  • 流水字段：权益流水号、用户 ID、昵称、权益类型、权益内容、关联订单号、发放人和发放时间
  • 不在流水列表展示发放类型、发放来源和备注
  • 权益内容：玩家会籍显示“12 个月”或“3 个月”；经验值显示“500 经验值”或“100 经验值”；贡献值显示具体数值，如“20”或“30”
  • 用户 ID、昵称和关联订单号均支持点击进入对应用户档案或订单详情
流水筛选与分页
  • 支持按关键词、权益类型和全局开始时间筛选
  • 权益类型包括经验值、贡献值和玩家会籍
  • 不提供发放类型筛选
  • 复用全局开始时间组件，日期精确到年月日、时间精确到分钟，不筛选结束时间
  • 使用后台统一分页组件，支持 10、20、50、100 条每页及跳转页码
手动发放权益
  • 仅支持单个用户发放，支持搜索并选择用户 ID 或昵称
  • 可选择发放经验值、贡献值或玩家会籍；经验值和贡献值必须填写正整数
  • 玩家会籍：默认发放 12 个月，仅支持选择整月时长，可选择 1、3、6、12 个月
  • 手动会籍发放不绑定订单；系统会籍发放仅在会费订单支付成功后生成并绑定订单号
  • 手动会籍仅支持追加，不支持撤销、扣回、删除或修改既有会籍
会籍计算规则
  • 会费订单成功后系统默认发放 12 个月玩家会籍
  • 新用户或会籍已到期用户，从发放日开始计算会籍
  • 当前有效会籍用户追加整月会籍时，从当前权益到期日继续计算
  • 权益流水完整保留历史记录；经验值和贡献值错误数据继续按照原模块冲正规则处理

  • 服务器编码：展示服务器唯一编码

  • 玩家数量：展示归属该服务器的当前玩家数

  • 配置名称、编码、城市、负责人和状态
  • 服务器名称和编码不可重复

  • 后台账号仅能查看授权服务器的数据
  • 用户迁移后历史活动、订单、贡献和内容保留原始归属

9. 任务管理

需求点需求描述
任务列表字段
  • 任务名称：展示任务卡名称
  • 任务星级：展示一星至五星
  • 任务周期：展示任务开始、结束和每周交付时间
  • 关联笨笨老大：展示负责分配和审批该任务的笨笨老大
  • 奖励内容：展示经验值、贡献值和奖金的配置结果
  • 回传附件：展示完成任务时是否必须上传附件
  • 附件模板：展示任务是否提供可下载模板
  • 任务状态：展示已发布、已下架或已结束
任务配置字段
  • 任务名称：填写单行任务标题
  • 任务星级：选择一星、二星、三星、四星或五星
  • 任务目的：填写任务目标和预期价值
  • 任务内容：填写用户需要执行的具体内容
  • 完成标准：填写任务验收条件
  • 任务周期：配置开始时间、结束时间和每周固定交付时间
  • 关联笨笨老大：选择负责该任务分配和审批的笨笨老大
  • 适用服务器：配置任务可见及可分配范围
  • 固定星级任务支持重复或周期发放，具体发放周期在任务中配置
任务奖励配置
  • 奖励类型包括经验值、贡献值和奖金
  • 三种奖励可分别启用或关闭
  • 可仅配置一种奖励，也可同时配置两种或三种奖励
  • 经验值：配置审批通过后发放的经验值数量
  • 贡献值：配置审批通过后发放的贡献值数量
  • 奖金：配置审批通过后发放的奖金金额
  • 至少启用一种奖励，未启用奖励不产生对应流水
  • 奖励使用任务提交记录做幂等校验，不得重复发放
