### 0.2 角色定义与升级链路（M1 拍板四层模型）

```
游客（未登录）
   │ 任意触发点点击 → 微信一键登录（手机号+昵称+头像）→ 新账号补充个人资料
   ▼
普通用户（已登录，未签到过任何 MIP 活动）
   │ 报名并签到任意一场 MIP 活动（系统自动升级）
   ▼
嘉宾（签到过 ≥1 场 MIP 活动）
   │ 支付会费开通玩家（需求文档口径 6600 元；重画页金额为占位 W18）
   ▼
玩家（付费会员）
```

> RD 另定义「访客 = 访问其他人主页的用户」——M1 口径中它不是独立角色层级，而是各角色的一种行为状态，本流程不单列一章；访客相关规则（记录/红点）归入嘉宾/玩家「我的页」小节。

### 0.3 全局登录链路（所有角色通用，M1 00:00–00:03）

- **触发点清单**：
  - 活动详情页：`分享`、`立刻报名`、`参与人数`（3 个，M1 00:01:38；RD「游客权限」表写 `参与人数`，设计稿帧按钮文案为「参与人数45」）。
  - 机会页-项目机会：`发布机会`、`玩家登录`、`去成为玩家解锁权限`（3 个，M1 00:02:22–00:03:27）。
  - 机会页-人才合作：`筛选`、`玩家登录`、`去成为玩家解锁权限`（3 个，M1 00:03:50）。
  - 我的页：`头像`、`经验值卡片`、`活动`、`名片`、`订单`、`设置`（6 个，M1 00:08:52；RD image 4 同）。
- **登录方式**：微信一键登录，获取 **手机号、昵称、头像** 三个信息（M1 00:00:43）。
- **登录后**：新账号（无用户信息）→ 进入补充个人资料页 → 填写完成后「完成或关闭」都**返回触发登录的原页面**（M1 00:01:59）。
- 老账号：直接回到触发登录的原页面，继续原操作意图（M1 00:03:38「登录完之后该走什么流程走什么」）。

## 一、J0 系统共享流程：扫码签到

### J0-01 扫码签到（已登录） `[流程图 J0-01 → scene: scan-signin]`

- **页面目的**：现场用户扫活动二维码完成签到，系统落到对应活动详情页并给出成功反馈。
- **可见元素**：活动详情页（已签到态）——头图、活动标题「MIP反人性早会第328场」、标签（仅玩家/沙龙）、时间地点、参与人数 45/50、活动介绍/主办方/报名须知、「与你互动」区块（我的心动 2 / 对我心动 2 / 活动反馈入口）、底部主按钮呈已签到态。
- **可点按钮及反馈**：
  - `与你互动`：展开/收起互动区块；`我的心动 2`、`对我心动 2` → 进入心动值页（J3-06，纯查看）；`活动反馈` → 活动反馈页（按签到状态显示，M1 00:47:43）。
  - `参与人数` → 参与人列表（J2-02/J3 同页按角色差异）。
- **该角色不可见/不可点**：底部主按钮不再可重复报名（已签到态）。
- **系统反馈**：扫码后不停留扫码页，直接定位活动详情页并弹「签到成功」提示（M1 00:46:24）。
- **SOT 推理**：布局取 `1818_17142_活动详情-已签到` 设计稿帧；「签到成功」toast 设计稿未呈现，按 M1 口径补画（记入偏差报告 D-06 组）。活动详情页元素（分享/参与人数/报名）与 1861_17860 帧一致。

### J0-02 扫码签到（未登录分支） `[流程图 J0-02 → scene: login-sheet]`

- **页面目的**：未登录用户扫码时先完成登录，再获得签到成功反馈。
- **可见元素**：活动详情页 + 底部半屏登录弹层（微信一键登录：手机号快捷获取 + 微信昵称/头像授权确认）。
- **可点按钮及反馈**：
  - `微信一键登录（获取手机号）` → 系统获取手机号/昵称/头像 → 新账号进入补充资料（J1-03）→ 完成或关闭 → 返回活动详情页 → 提示「签到成功」。
  - `关闭` → 返回活动详情页，不签到。
- **该角色不可见/不可点**：登录前任何签到反馈不出现。
- **SOT 推理**：登录弹层设计稿未呈现（M1 00:00「这里好像没有做登录的那个页面」），按 M1 口径自拟半屏弹层：先确认手机号，再带出昵称头像；样式遵循 Design System（#202020 表面、#fcdf03 主按钮、黑描边）。记入偏差报告 D-07。

## 二、J1 游客（未登录）

> 游客的唯一主线就是「被登录拦截」：M1 00:09:27「游客只有登录」。任何触发点点击 → 登录 → （新账号）补资料 → 回到原页继续原意图。

### 1.1 活动详情页（游客视角） `[流程图 J1-01 → scene: activity-detail-guest]`

- **页面目的**：展示活动信息，诱导游客登录报名。
- **可见元素**（`1861_17860_活动-首页-详情` 帧实测布局）：导航栏（返回/主页胶囊 + `分享`）；头图 375×211；活动标题「MIP反人性早会第328场」16/600；标签 Chip「仅玩家」「沙龙」；时间地点行；价格「¥589」；中部参与人区块：`参与人数45 /50` + 六个头像（铁锤妹妹/Ame/Dylan/Nehz/大鹅飞飞/哈库呐玛）+ `查看更多`；下部介绍卡（活动介绍/主办方/报名须知 分段 + 二维码指引卡 351×393 @y585）；底部操作条：`指引` + 主按钮 `立刻报名 ¥589`（351×56 光晕外圈 + 327×40 黄色内芯）。
- **可点按钮及反馈**（全部触发登录，M1 00:01:38）：
  1. `分享` → 弹登录 → 登录完成后继续分享动作（海报为固定模板，自动填充活动标题）。
  2. `参与人数45` → 弹登录 → 完成后进入参与人列表。
  3. `立刻报名` → 弹登录 → 完成后进入活动报名订单页。
  - 以上任一触发：微信一键登录弹层（J0-02 同组件）→ 新账号补资料（1.2）→ 返回本页继续原意图。
- **该角色不可见/不可点**：无「与你互动」区块（未签到）；无可点击的参与人头像（头像点击 = 查看档案，属登录后能力）。
- **SOT 推理**：布局与相对位置全部取自 1861_17860 帧实测换算；底部主按钮文案设计稿为「立刻报名」，RD 写「立即报名」——取设计稿帧内实测文案「立刻报名」为呈现口径、RD 文案记为同义待统一（不阻塞流程）。分享/参与人数/报名三触发点按 M1。

### 1.2 补充个人资料页（新账号） `[流程图 J1-03 → scene: profile-fill]`

- **页面目的**：新账号完善个人信息，完成注册闭环。
- **可见元素**（`1774_41143_编辑信息` 帧实测布局）：导航标题「填写信息」；头像位 + `更换头像`；`*请输入您的昵称`；`性别` 男/女选择；「基础信息——吸引更多适合你的资源和人脉~」；`代表行业` 行业标签选择；`当前身份状态` 九选一 Chip（广告营销/品牌主理人/激情创业者/公司负责人/自由探索者/大厂精英/专业投资人/在读学生…）；`一句话介绍你的工作和背景` 多行输入 0/300；底部主按钮 `保存`。
- **可点按钮及反馈**：`保存` → 校验必填（昵称/头像）→ 保存成功 → **返回触发登录的原页面**（M1 00:01:59「完成或关闭，都返回这个页面」）。
- **该角色不可见/不可点**：未填必填项时 `保存` 置灰拦截。
- **SOT 推理**：页面复用已有「编辑信息」帧（M1 00:01:23「这个之前是已经写好了的」），布局按设计稿；「完成或关闭都返回原页」按 M1，设计稿无此返回规则标注。

### 1.6 订单确认页 `[流程图 J1-07 → scene: order-confirm]`
