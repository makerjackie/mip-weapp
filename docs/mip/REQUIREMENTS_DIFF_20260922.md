## 未完成与外部验收

拉取时新增的 47 个后台 action 全为占位：27 个抛 `NOT_IMPLEMENTED`、17 个固定空列表、3 个固定 null。本轮已接入其中的账号、档案、合作卡、贡献、视频、活动草稿与运行时、权益、机会删除和活动反馈导出。**通用名片管理** `mip.admin.cards.*` 仍是空列表/`NOT_IMPLEMENTED`，不能把它当作已上线功能：小程序名片实际由用户档案生成，而旧 `mip_business_cards` 表既没有 AppID/所有者，也不与现有名片绑定；直接往表里写一份“管理员名片”会制造两份相互矛盾的事实。需将管理能力接到真实用户档案、模板和历史版本后再开放。`mip.admin.roles.create` 仍是不可从 Web 调用的旧占位；当前正式角色为七种固定角色，使用已有 `roles.set` 和权限模板管理，不凭空开放自定义角色。

后台 PRD 的 8 月 25 日稿写了手机号/密码登录，与本工程已接受的 ADR 0006 微信小程序扫码确认登录冲突。本轮沿用 ADR 的登录链路；此冲突尚未视为“已实现密码登录”。

短信签名/模板和供应商配置、微信订阅模板和授权、数据库迁移部署、云函数部署及真机手机号/支付/扫码验收必须分别提供证据。本轮不把本地代码、构建或模拟测试写成现网完成。
