# 玩家权益入口与后台角色分离

甲方反馈：玩家权益入口难找；新用户不能默认成为管理员，后台角色需单独配置。此次只调整这两项，不改变未决的普通/嘉宾/玩家分类与主分会规则。

- 用户详情将「补录会员」改为醒目的「开通玩家权益」，仍复用原有会员链、时长、原因、版本和幂等操作；仅具有平台会员查看及调整权限的操作者显示。
- 用户详情移除「设置角色」快捷动作；后台角色由「系统管理 → 后台账号」单独配置。已有后台授权只读展示为「后台角色」，不与玩家身份混用。
- 新用户注册只创建业务身份及会员并发链，不创建后台账号、角色绑定或会籍权益。玩家开通不授予后台权限。Owner 初始化属于明确的维护操作。
- 测试库两个现存 Owner 绑定均发生在注册之后，且各有 `admin.owner.bootstrap` 审计记录；这是历史显式授权，不是新注册默认授权。本轮未撤销这些此前指定的管理员。

工具栏截图是同一真实测试账号、同一视口的局部对比；完整原图留在受保护本机目录。局部包含全部用户详情操作按钮，只排除个人资料区域，未重绘或拼造数据；不能以工具栏截图替代注册/权限验证。此次新入口没有另行提供视觉原型原图，依据本次甲方文字反馈实施，公开站如实注明。

本轮不向真实账号追加不可撤销的会员时长，不创建/扩大后台权限。真实微信新用户首次注册与人工赠送会籍的完整旅程须分别验收；代码合同与打开/取消表单不冒充实际发放完成。
