# 岗位模板专项权限审查

这是执行计划 W09 的专项代码审查记录，由本轮执行者完成；不是独立安全审计，也不是实际账号跨范围验收。产品标准仍为 [A02/A03/K05](../../../../admin-web/ACCEPTANCE.md)。

## 已核对的授权路径

| 核对项 | 代码及证明 | 结论 |
| --- | --- | --- |
| 权限上限 | `role-template-policy.js` 与 `capabilities.js`：基础角色上限、现有角色策略、启用岗位模板取交集 | 模板不能增加基础角色权限；同一用户的不同范围分别计算 |
| 缺失及停用模板 | 模板不存在、停用、基础角色不匹配、权限 JSON 非法或重复均拒绝 | 不降级为原基础角色的全部权限 |
| AppID 与范围 | 模板、绑定、角色策略 SQL 连接均包含 AppID；写入事务重新锁定当前绑定和用户 | 不能借用其他 AppID 的同号模板，读取后撤权仍阻止写入 |
| 账号绑定 | `repositories/admin-accounts.js`：版本比较、旧绑定撤销、同用户/角色/范围绑定复用、模板权限再次校验 | 不把旧基础角色全权绑定遗留在模板绑定旁；账号停用撤销绑定 |
| 超管保护 | 模板排除 `PLATFORM_OWNER`，模板绑定拒绝超管；账号变更拒绝自身和受保护超管 | 本轮没有创建新超管角色或给真实用户授权 |
| 部署自包含 | 同一 authored policy 生成到八个消费者，生成检查及各函数回归通过 | 没有跨仓库或仓库外的运行依赖 |
| 启用顺序 | 094/095 已应用；九个业务函数下载 ZIP 与本地全部 JS 匹配，MySQL 健康通过 | 只有兼容消费者全到位后才允许开放绑定写入 |

聚焦回归入口：`cloudfunctions/mip-admin-api/tests/role-templates.test.js`、`mutation-authorization.test.js`、`admin-account-runtime.test.js`，以及各消费者的授权测试。覆盖模板收窄、两范围分离、非法/停用模板、跨 AppID、事务内撤权、超管保护、版本与幂等；完整门禁结果见本目录 README。

## 运行证据边界

真实云端已验证未绑定模板的创建、同请求重放、更新版本、过期版本拒绝、复制及停用；四个验收模板均为 INACTIVE、bindingCount 为 0。全消费者代码回读及真实业务烟测后，已将管理 API 的绑定入口设为启用，配置与健康检查通过；实际结果见 [启用证据](template-bindings.public.json)和[真实读回](template-readback.public.json)。开启功能开关不等于给任何用户授予权限。

普通代码部署会从现有管理 API 配置保留绑定开关；新环境默认关闭，只有显式配置 true/false 才改变它。部署 helper 的回归覆盖原来已启用配置不被空配置覆盖、显式关闭及非法值拒绝，防止后续发版意外关闭入口。消费者读权限仍按真实绑定与模板计算，开关不会让它们忽略已有模板限制。

A03 整条仍需使用受控测试账号验证：两个服务器、多个绑定、模板收窄/停用、旧会话与撤权后操作、恢复与审计。不拿维护者的真实超管绑定做破坏性测试；不能以本审查或一次健康检查宣称完整权限旅程通过。

## 回滚下限

启用后不得回退为忽略模板的旧授权代码。关闭写入入口不会撤销已有模板限制；保持拒绝或向前修复。兼容迁移及新写入保留，数据库不以删除授权或历史记录作为回滚手段。发布前函数与数据库备份保存在维护者本机，位置见 [RELEASE.md](RELEASE.md)。
