## 发现并修复

- 任务、Banner 的 Web 保存依赖不存在的微信云调用上下文。改用仓库统一的微信 HTTPS 审核客户端；任务的签名内部请求传递服务端确认的 OpenID。身份、签名、应用匹配及审核失败仍严格拒绝；长文本完整分块审核。
- 云端任务/Banner 的公网出口关闭，HTTP 审核接口不可达。补齐现有微信 API 发布规则并回读，VPC、角色、入站权限和代码保持原值，不添加保活定时器。
- 不同运营操作共用同一个表单实例，旧服务器的名称、简介串入新消息、公告。以操作对象隔离表单生命周期；不同表单的控件 ID 独立，隐藏标签不再串入视频、知识等新页面。
- 知识编辑把 `_canSave` 界面元数据送入严格业务合同，导致新建成功而编辑失败。只剔除已知界面字段，保留未知字段拒绝和版本保护。
- 案例留空的可选日期、类型经 JSON 传输被省略，服务端拒绝草稿。传输明确的 null，保持服务端完整草稿合同。
- 审计关键词未参与服务端查询，角色列读取了错误字段。补齐参数化关键词查询及有效角色字段；最后补测发现主审计列表漏接共用操作名格式化，接入后显示中文动作。
- 指定消息收件人原来需要手写内部引用。改为按姓名搜索、多选服务端返回的接收人，服务端仍校验作用范围。
- 编辑后返回丢失内容分区和筛选。编辑 URL 携带并校验原列表查询，保存/取消均恢复；新建合作卡和案例返回内容分区。消息的指定人数来自已保存接收人配置，投递快照统计单列，避免草稿显示成 0 人。
- 机会详情未显示远程合作地点、结束操作标题错误；视频及详情的部分状态未显示中文；贡献规则列误标经验奖励；任务无奖励校验提示过于笼统。分别修复。
