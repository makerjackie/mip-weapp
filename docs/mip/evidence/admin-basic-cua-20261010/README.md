## 发现并修复的订单搜索问题

中文活动名称或包含省略号的显示订单号搜索，会使订单页返回 `SERVICE_UNAVAILABLE`；清除搜索后恢复列表。真实 MySQL 执行确认 `Error 1270: Illegal mix of collations ... for operation 'like'`：UUID 和商户订单号是 `ascii_bin`，不能直接与 Unicode 关键词执行该比较。

源码 `628f539f` 在订单列表与汇总共用的筛选构造中，将这两个 ASCII 列转换为 UTF-8，并显式保留 binary 比较。没有更改权限、数据库结构、金额、分页或 LIKE 的字面通配符转义。小程序侧不直接消费这条管理列表 action；中立 DTO 和契约不变。修复后的真实 SQL 返回 5 条中文标题匹配记录，显示订单号关键词正常返回 0 条。显示中的省略号不是通配符，搜索完整订单号或有效片段仍以实际字段为准。

- 新增回归覆盖列表/汇总一致、app 与服务器作用域、Unicode 及 `%` / `_` / 反斜杠的字面转义；订单专项 18 项通过。
- 完整 `pnpm verify:all` 最终 exit 0，根工程 1614 项、Web React 164 项及合同、类型、lint、构建等门禁通过。首次检查发现既有 SQL 断言仍要求旧表达式，更新断言后完整重跑通过。
- 仅重新部署 `mip-admin-api`，仓库官方部署 exit 0，函数 MySQL health 通过。下载代码包 SHA-256 与平台相同，277 个 JS/JSON（包括测试文件）与该提交源码逐字节一致。角色、运行时、内存、超时、网络、环境值、SDK 权限、触发器和网关均保留。[部署回读](deployment.json)。

## 保留的边界

- 导出：创建后弹窗关闭，但自动化未捕获到下载文件；浏览器安全策略拒绝打开内部下载记录页，因此没有继续绕过检查，也不记为下载成功。这项需要实际文件收据后才能通过。
- 刷新：一次重载曾显示空白，浏览器无捕获到的 JS 错误；再次重载恢复，随后完成草稿内容回读。根因证据不足，不能把此现象归因为代码缺陷或声称所有重载均无异常。
- 手机实际扫码、手机号、支付/退款、所有业务增删改和权限变更未验收；本轮没有上传微信版本、修改证书续期或退役 Cloudflare。
