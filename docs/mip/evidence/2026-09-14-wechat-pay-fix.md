# 微信支付修复与验收（2026-09-14）

## 修复范围

- 原生 CloudPay V2 支付通知按 `returnCode/resultCode` 解析，不强制要求查单响应中的 `tradeState`。保留平台调用边界、身份与金额校验、ledger 幂等。
- `queryOrder`、`refund`、`queryRefund` 使用官方下划线参数；解析原生退款查询的编号字段。
- ledger 验签字段补齐 `forSync` 和 `providerPaidAt`，解决查单和带付款时间的回调被内部鉴权拒绝的问题。
- 支付结果页直接读取当前订单，不等待订单列表或方案请求；查询异常停止连续轮询，保留刷新与订单入口。订单及退款文案使用用户可理解的表述。
- 部署脚本等待函数改为提升声明，修复首次等待部署完成时的初始化错误。

## 验证与证据边界

- 真实支付适配器/回调客户端对接 ledger 验签器的三条合同用例，修改前均以 `FORBIDDEN` 失败；修改后通过，同时覆盖字段篡改与移除。
- 支付、通知、ledger 的 84 项 Node 测试通过；页面异步请求与支付部署合同测试通过。此前完整 `pnpm verify:all` 已通过。
- 支付适配器、通知、退款 worker 和 ledger 代码已部署，CloudBase 配置、健康与受保护调用检查通过。未修改客户端支付成功即发放权益的安全边界。
- 云端只读探针使用不存在的订单，确认新签名被接受、订单仍被正确拒绝；探针没有写入付款事实。
- 用户于本次会话明确反馈会员支付已正常。活动付款、退款真机闭环仍待验收，不能由会员支付结果推定通过。
- 会员测试方案已配置为 10 分；商户与环境凭证仅存在本地/云端配置，不随本提交入库。
