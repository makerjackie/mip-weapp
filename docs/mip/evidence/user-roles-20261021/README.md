## 最终规则

- 匿名访客：未登录，仅会话状态，不伪造后台用户。普通用户：已登录，无有效玩家权益，也无有效活动签到。
- 嘉宾：至少一次报名 ATTENDED 且对应签到 ACTIVE；玩家：当前 ACTIVE 且在有效期内的权益。首次付费仍须审核，后台开通保留。
- 权益到期按有效签到回退；最后一次有效签到撤销后回到普通用户。产品角色不授予后台账号或权限。
- 成功报名但未签到的普通用户归入本场活动嘉宾名单，全局角色仍是普通用户；不提前获得签到互动权限。保留不公开和屏蔽设置。
- 头像、昵称、代表行业、当前身份、一句话介绍必填，性别选填；历史缺项用户在下次报名等受保护用户操作补齐。
- 人才合作候选为有效玩家，或已签到嘉宾且最近明确选择愿意加入花名册。跨活动与编辑旧反馈均取最新选择；不愿意即退出。保留人才隐私和屏蔽，浏览权限不变。

## 实现位置与边界

共享领域规则采用云函数内自包含副本：identity 的 product-role.js、profile-readiness.js 为规则源，admin/opportunities 等通过一致性测试对齐。会员权限继续 GUEST/PLAYER；productRole 单独展示 NORMAL/GUEST/PLAYER，匿名为 ANONYMOUS。

后台用户列表、详情、筛选与导出统一走服务端分页前分类；BFF 不再逐页裁剪普通用户。活动名单计数与明细都连接有效用户资料。人才查询先算资格、后分页，详情读取再校验公开资格。

消费者资料门槛只进入 identity/events/commerce/opportunities。banners/tasks/game 中的 assertAdminReady 是运营权限入口，保持独立的后台授权规则；新增回归用例防止把消费者资料门槛错误套到运营人员。

数据库追加迁移 113_roster_consent_lookup.sql（反馈按用户、更新时间索引），已在完整备份后应用至 mip_test。未修改生产数据库。代码和配置分开部署，回读九个测试函数的运行 ZIP，348 个源码文件相符，环境变量、VPC、角色、超时等保持一致。
