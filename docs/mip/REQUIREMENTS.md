# MIP 功能需求基线

本基线把已提供的全部能力纳入一个实现目标。工程可以分阶段和并行交付，但不以“里程碑一/二”裁剪最终范围。

## 1. 身份与访问

- 首次进入小程序必须先完成微信身份建立并确认两份协议；完成后，公开活动、机会和公开档案不要求付费会员、手机号或完整档案即可浏览。这里的“公开”是业务可见范围，不表示绕过微信身份和协议门禁。
- 报名、支付、发布、互动、查看受限资料和进入管理端前，必须完成协议确认和所需身份资料。
- 手机号、头像和昵称分别通过微信允许的用户操作获取；不承诺一次授权自动取得全部信息。
- 更换手机号必须经过微信手机号验证，并由服务端检查该手机号是否已绑定其他账号；重复绑定必须拒绝。
- 身份补全完成后返回触发动作前的页面和业务上下文。
- 微信会话失效时重新认证；不把“固定 30 天或 90 天免登录”作为服务端安全保证。
- 玩家是拥有有效付费权益的用户；其他用户为嘉宾。退款、到期或权益撤销后立即按嘉宾规则判断。

## 2. 城市分会与档案

- 平台和城市分会是一等范围。用户只有一个主分会，可以跨城市浏览和参与。
- 活动和机会可属于平台或一个城市分会。
- 城市管理员只能管理被授权分会；平台管理员可以跨分会管理。
- 用户档案中的公司、组织和职位只用于展示，不产生运营权限。
- 档案支持昵称、头像、身份状态、主行业、能力、城市、简介、公司经历、组织经历和隐私设置；公司与组织是两组独立的可排序经历，当前编辑器每组最多 12 条，展示字段仅为名称和角色。
- “谁看过我”只对本人可见；访问个人主页记一次，重复访问累计，列表按最新访问优先，并提供未读红点和已读状态。访问记录不向被访问者以外的用户公开。
- 行业采用两级标签：一级只分组不可选，二级可选；通用筛选支持多选，个人主行业最多一个。
- 城市和行业标签先使用仓库默认数据，后续通过运营配置替换。
- 平台运营可维护城市分会目录；分会标识创建后不可修改，已有成员、城市管理员或已发布内容时不能停用，也不物理删除。

## 3. 会员、订单与支付

- 用户可查看会员方案、下单、支付、查看订单和退款状态。
- 用户订单按“全部 / 待使用 / 已完成 / 已退款”筛选；该使用状态由服务端结合订单、报名和权益事实投影，不使用客户端支付态替代。
- 客户端只提交购买意图；金额、资格、权益生效、退款和发货由服务端 ledger 决定。
- `requestPayment` 返回成功不代表玩家权益已生效，页面必须支持待确认状态。
- 正式 AppID、商户号、证书和支付回调均通过本地/部署配置接入；缺少配置时使用 disabled 或 test adapter，不伪造真实支付成功。
- 玩家入会邀请人在一个有效会员期内固定；自然流归属“MIP 平台”。
- 玩家成长/VIP 页提供会员邀请与续费入口：邀请 token 由会员服务生成，续费进入统一会员方案和支付流水，不在成长页复制支付逻辑。

## 4. 活动

- 首页按城市展示近期和已结束活动，支持城市、状态、标题搜索和日期筛选；日期筛选支持单日兼容以及包含起止日的日期区间，开始日期晚于结束日期时拒绝请求。
- 活动卡展示封面、时间、地点、状态、参与人数、玩家限制和活动类型。
- 活动详情展示图文、主办方、报名须知、地点、参与人、分享和报名入口。后台可上传最多 12 张活动介绍图片，图片有说明文字，可上移、下移、移除和预览；服务端保存排序和版本，前台只展示已绑定的可用媒体。
- 活动不经过人工审批即可发布；内容安全失败时不得公开。
- 免费自动报名、审核报名、候补和付费报名均由服务端状态机处理。
- 有报名或订单的活动不得物理删除，只能下架或取消。
- 嘉宾活动邀请归属按活动记录；无邀请时归属“MIP 平台”。
- 报名取消时间由活动或平台配置；没有活动级覆盖时使用平台默认值，仓库默认 24 小时且允许配置 0–720 小时；付费取消先进入退款流程。
- 活动可关闭相册，并可配置参与者照片自动发布或审核后发布；该结论由服务端活动事实决定。
- 只有当前 `REGISTERED` / `ATTENDED` 参与者可以提交照片。客户端先压缩，服务端仍校验媒体 owner、`READY`、`EVENT_ALBUM` purpose 和图片内容安全完成状态。
- 公开相册只分页返回已发布照片；本人可查看待审/拒绝状态并按版本撤回。审核、拒绝和撤回保留业务事实，不物理删除记录。

## 5. 签到、心动与反馈

- 管理员可在小程序管理分包生成并下载活动签到海报，普通用户不可见管理入口。
- 用户扫码进入活动详情，完成登录、报名或支付后，再由服务端判断是否可以签到。
- 可下载静态二维码只能提供活动时间窗内的尽力而为现场约束，不能技术上保证二维码未被转发；严格现场模式预留轮换码适配器。
- 每位已签到用户在一场活动中最多选择一位参与者“心动”，可取消或改选，不可选择自己。
- “我点过心动的人”和“对我心动的人”仅本人可见；运营只在治理和审计能力下访问。
- 每位已签到用户每场活动可提交一份反馈并修改；反馈正文仅运营可见。

## 6. 机会、引荐与感兴趣

- 机会广场按发布时间倒序展示招募中和已结束机会，支持角色、行业、能力、城市和关键词筛选；人才入口提供“只搜玩家 / 全局搜索”切换，默认全局搜索，能力筛选可多选。
- 发布人可创建、编辑、结束机会；编辑后刷新发布时间和排序。发布时可从当前可见的有效玩家中选择最多 8 名组队成员，成员可移除后重新选择；普通用户不能删除，平台负责人和平台运营可审计归档没有关联业务事实的草稿。
- 机会默认经过内容安全检查后发布，不设置人工预审；运营可下架。
- 每位用户对每条机会最多一条“我想引荐”关系。发起人从当前可见的玩家或嘉宾中选择一位被引荐人，可更换对象、取消后再次提交；服务端按 AppID、有效账号和双向屏蔽关系重查目标。
- “相关机会”分别展示本人发布的机会和引荐给本人的机会；被引荐列表只来自当前关系中的被引荐人事实，不用机会发布人或消息载荷推断，并支持未读状态和分页。
- 每位用户对每条机会最多一条有效“我想引荐”关系、对另一位用户最多一条有效“我感兴趣”关系；两者都可取消后再次提交，不能通过重复点击产生多条有效关系。
- 机会发布人可以编辑、结束机会；后台可按授权处理机会状态，但不能绕过服务端关联事实物理删除。
- 完成身份和协议门禁的用户可在机会详情发布评论；机会结束后可提交 1–5 分项目评价。机会发布人和团队历史成员由服务端标记为参与人，普通用户不能自行标记；只有机会发布人或当前有效团队成员可以打 call。评论支持 30 分钟内编辑、软删除、分页、幂等打 call 和举报，并按双向屏蔽关系过滤。
- 后台使用 `messages.manage` 在机会所属平台或分会范围内配置评论、项目评价、打 call 和发布前审核；评论审核、举报结论均使用乐观锁并追加审计。
- 引荐和感兴趣先生成站内消息；微信消息只作为授权和时效允许时的补充。

## 7. 合作卡与超级案例

- 一个用户可创建多张合作卡，但六种合作角色各最多一张。
- 稳定角色 key 为 `connector`、`business_builder`、`capital_operator`、`strategist`、`visual_designer`、`delivery_lead`；展示名分别为皮条客、生意佬、暴发户、狗策划、死美工、老保姆。
- 合作卡保存角色定位、目标、角色专属字段和六项用户自评能力，详情使用雷达图展示。
- 超级案例保存项目名称、一句话说明、起止时间、职责、主营城市、行业/类型、详细说明和展示素材。
- 合作卡和超级案例支持 AI 语音填写：录音转为可编辑草稿，用户确认后才保存正式内容。
- 合作卡编辑中点击“预览”时，先保存当前已填写信息，再打开预览；未成功保存时不得把预览当成已保存结果。
- AI 结果不得自动授予角色、等级、权益或运营权限；音频按隐私和保留期策略清理。

## 8. 成长体系

- 支持等级、经验值、贡献值、游戏币、权益展示和流水查询；三类余额与流水都以服务端事实为准。
- 奖励行为由服务端固定规则产生，包含幂等键、每日上限和关联业务；页面不得自行加分。
- 等级门槛由运营配置并保持递增；已使用等级只能停用，不能破坏性删除。
- 具体等级数量、门槛和奖励数值先使用可替换默认配置，正式验收前由业务方确认。
- 人工调整如开放，必须是独立 capability，并生成不可变审计和成长流水。
- 游戏币发放和消费只接受受信内部事件或具有 `growth.adjust` capability 的管理动作；固定内部规则不接收客户端金额，消费后余额不得为负数。
- 基础资料展示当前佩戴勋章；用户可查看本人已获授勋章，并选择最多 3 枚佩戴。
- 运营端维护勋章目录、启停和排序，受控授予或撤销用户勋章并写入审计；仍在佩戴的获授事实必须先取消佩戴才能撤销。

## 9. 任务卡

- 运营端可新增、编辑、发布、下架和软删除任务卡，配置全员或指定成员、适用成长等级精确集合、截止时间、完成说明、经验值奖励、附件要求和最多一个可下载模板；未配置适用等级表示全部等级。
- 指定成员只能从当前 AppID 的有效用户中搜索和派发；派发撤销只改状态，不能删除历史。
- 用户只能查看本人当前分配且符合当前成长等级的任务；服务端在列表、详情和完成提交时都按当前经验重新判级，不能接受客户端自报等级。截止后保留记录和“已截止”状态，不再接受完成提交。
- 每个用户对同一任务最多形成一条完成事实；附件、任务内容和奖励值按完成时快照保存。
- 任务完成只发放一次经验值，不发放游戏币、勋章或客户端指定的其他奖励；完成事实与成长流水必须在同一服务端事务中收敛。
- 运营端可以查看、筛选和导出完成流水；失败或撤销状态不得冒充已发放奖励。

## 10. 团队 PK、赛季与排行榜

- 该模块只对当前拥有有效付费权益的玩家开放；嘉宾不能通过本地状态、支付调起结果或客户端参数进入。
- 支持赛季配置、团队及成员历史、每周对阵、当前赛况、历史结果、用户可见规则和队伍大本营。
- 队伍大本营展示当前赛季、队伍、城市分会、成员和服务端经验值，并按可替换阈值映射中性视觉等级；正式规则和视觉到位后只替换配置或资产。
- 支持团队半年榜、团队年度榜、个人赛季榜和个人累计榜；团队榜分别使用赛季结束时间向前 6 个月和 12 个月，个人赛季榜使用赛季起止时间，排行榜可按 MIP 城市分会筛选。
- 客户端不能提交 score、points 或任何分数字段。每周赛况和排行榜由 `mip-game-api` 从当前 AppID 的成长流水、成长账户及服务端赛季周期生成。
- 周赛结算和排行榜生成保留服务端快照，后续成长值变化不重写历史结果。
- 排名与队伍大本营仍只使用经验值。每周赛结算后，胜方在结算周期末仍属于该队伍的有效用户按服务端固定规则获得游戏币；正式赛事规则、阈值、文案和队伍大本营视觉未提供时使用朴素、可替换的中性默认值。

## 11. 消息

- 站内消息是所有定向业务通知的权威入口，支持未读数、列表、已读和业务页面跳转。
- 微信订阅消息、客服消息和服务号消息是可选 adapter；缺少模板或授权时不得阻断业务事实落库。
- 报名、支付、退款、签到、心动、机会引荐、感兴趣、成长变更、等级提升、游戏币和运营通知均进入统一 outbox。
- 普通经验值变化保留站内消息；只有服务端确认跨越等级门槛时才产生升级弹窗。游戏币变化使用 `GAME` 消息并只跳转到受信游戏页面。
- 通知 worker 默认不安装高频定时器，避免持续唤醒共享 Serverless MySQL。

## 12. 管理端

- 保留当前小程序管理分包；服务端接口按未来独立 Web 管理后台可复用的标准设计。
- 平台角色至少包含超级管理员、运营人员、财务人员；城市分会包含城市管理员；活动包含负责人、管理员和现场工作人员。
- 用户管理支持组合筛选、脱敏查看、黑白名单、档案查看、可授权字段编辑和导出。
- 活动管理支持增改、发布/下架、参与者、签到、相册审核、订单和导出；相册审核使用独立 `events.album.manage` capability。
- 机会管理支持查看、下架、状态处理和审计。
- 成长管理支持等级、门槛、权益、流水和受控人工调整。
- 任务管理支持任务卡、成员派发、模板、截止窗口、完成流水和导出；勋章管理支持目录、授予、撤销和审计。
- 游戏化管理支持赛季、队伍、有效会员成员、每周对阵、服务端结算和排行榜快照，不提供手工录入分数入口。
- 手机号原文、导出、退款、角色变更和人工调整分别使用敏感 capability，并写审计日志。

## 13. 可替换配置

以下项目不阻塞代码完成，但真实验收前必须替换：

- 正式小程序 AppID、CloudBase 环境和微信支付商户配置；
- 服务协议、隐私协议正式正文；
- 订阅消息模板、服务号和客服消息配置；
- 正式行业/城市标签、城市分会清单；
- 等级门槛、奖励值、权益和每日上限；
- Figma 新文件已可读取，代表 frame 与入口资产已固定；正式勋章目录图片以及正式团队 PK/赛季规则、排行阈值和队伍大本营视觉仍使用可替换配置；
- 支持电话、Banner、视频号地址、活动与超级案例默认封面；
- AI 语音供应商、数据处理协议和音频保留期。

## 14. 飞书 AME 2026-08-24 增补范围

2026-08-24 从 AME 需求看板过滤视图导出的 110 条数据，除与固定 81 项 PRD 重复的活动、机会、会员、任务、游戏化和管理能力外，还出现以下增补条目。原始字段和行序见 [飞书需求看板快照](sources/feishu/MIP1.1.0需求看板-2026-08-24.md)；源表中的 `未开始`、`待评审` 只表示产品维护状态，不表示仓库实现状态。

### 14.1 笨笨盲盒

- P3 条目包含盲盒游戏界面与动画、游戏币发放/余额/流水/核销、卡牌背包、带游戏规则/兑换规则/稀有度的盲盒详情，以及抽取特效动画。
- 当前已复用权威游戏币账户与不可变流水，实现盲盒目录、卡牌库存、服务端抽取、背包、余额/流水、规则详情、抽取动画和 `game.manage` 管理配置。
- 源表未提供的概率、保底、库存、兑换规则和正式视觉使用可替换的后台配置与中性默认值；抽取结果、扣减金额、防负余额、库存核销和幂等结果均由服务端事务决定。正式规则和视觉仍需产品验收后替换。

### 14.2 AI 机会撮合

- P3 条目要求根据发布内容匹配人才和项目。
- 用户从本人已发布的机会发起撮合；服务端按合作角色、行业、能力、城市分会或城市范围生成可分页的人才和项目结果，并保存来源版本、设置版本、结果版本、分数、解释与反馈。
- 默认 provider 为可重复的本地规则。人才权重为角色 45、行业 20、能力 20、范围 15；项目权重为角色 35、行业 25、能力 25、范围 15。平台或城市分会运营可修改两类最低分、最大候选数和外部 provider 开关。
- 客户端和外部 provider 只接收请求范围内的签名候选引用；provider 的其余输入仅含候选类型、本地分数和匿名信号键/权重，不含人才用户 ID、分会/城市/标签内部主键。返回值必须是完整、不重复的候选排列和 0–100 分数。超时、异常或非法结果安全降级到本地 provider，不阻断撮合。
- 候选读取实时复核 AppID、发布状态、用户状态、公开字段、双向屏蔽、可发现权限和撮合范围；主分会未公开时不参与范围信号，也不出现在解释中。用户可关闭撮合、人才推荐、项目推荐或被人才撮合发现。

### 14.3 热点与知识付费

- P3 条目包含每日更新热点新闻、可配置信息渠道、行业内容分类、MIP 玩家攻略（图文、网页、视频）、私密视频号列表、行业专家分享，以及后台知识库配置。
- 热点 Agent 采用运营人员显式触发的 JSON Feed / RSS 受控采集，不安装定时器；单次采集必须限制 HTTPS 来源、响应时长/大小/条数，按外部 ID 与内容摘要去重并记录来源审计。采集内容进入审核，不能自动发布；私密视频号内容由运营人员人工配置。
- 用户端提供行业分类、内容类型/访问类型筛选、搜索、列表、详情、网页/视频号交付和评论。未解锁时不得返回正文、外链或视频号参数。
- `FREE`、`MEMBER`、`MEMBER_OR_PAID` 构成内容访问合同。单内容商品、价格、解锁期限和退款策略为服务端配置；在正式规则提供前使用可替换 TEST 目录，默认 `990` 分，不能冒充正式价格。
- 单内容付费复用 `mip_orders`，但必须使用 `CONTENT` 类型、不可变商品快照和独立阅读权益。支付 disabled 时明确关闭；只有 ledger 确认支付后才能发放权益。默认退款为访问前、配置窗口内的剩余全额退款，首次返回受保护正文后不得退款。
- 评论设置、评论和举报使用跨内容目标合同；知识内容用户端与管理端已接入，机会域保留既有评论实现。评论写入仍要求身份门禁、内容安全、幂等、屏蔽过滤和审核能力。

### 14.4 增补消息与用户权限

- 用户端“我的”提供评论、机会撮合和热点通知开关，以及撮合总开关、人才推荐、项目推荐、被发现和平台/主分会范围设置。评论与撮合通知默认开启，热点通知默认关闭；撮合及两类推荐默认开启，被发现默认开启且范围默认为主分会。
