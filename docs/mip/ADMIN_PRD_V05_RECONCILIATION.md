## 新增来源

该提交新增了 MIP 小程序公开主体信息、后台管理系统 V0.5 需求、2026-08-24 评审会议纪要和静态 HTML 原型。其中可公开的运营主体、域名和 ICP 备案号已进入品牌配置与“关于 MIP”页面。正式 AppID、原始 ID、CloudBase 环境 ID 和支付商户号仍是本地或部署配置，不写入仓库文档和前端代码。

## 采纳与落地

| V0.5 信息 | 当前处理 | 原因 |
| --- | --- | --- |
| 管理员必须先是已注册小程序用户 | 采纳 | 角色绑定只能指向当前 AppID 下的 `ACTIVE` 用户，不新建“未注册管理员”身份。 |
| 菜单勾选和敏感权限分开 | 采纳为展示与授权分层 | 菜单只做可见性；手机号、导出、退款、角色和人工调整继续使用独立 capability 和审计。 |
| 权益可系统发放或人工发放，保留明细 | 采纳 | 两种来源都进入服务端权益/成长流水和审计，客户端不直接改玩家状态。 |
| 奖金只记录线下发放 | 采纳为非目标 | 当前不做在线奖金支付；如后续记录，只作可审计的线下事实。 |
| 活动标签最多 5 个字，可启停，停用不破坏历史 | 采纳并补齐校验 | 新建/编辑 TAG 统一限制 1–5 字；历史关联不物理删除。 |
| 活动发布前手机预览、场地跳现有 H5、前台统一显示下架 | 采纳交互目标 | 预览复用未发布草稿投影；H5 只在有受信配置时启用；服务端仍保留取消、下架等领域事实。 |
| 活动报名/缴费/参与人归一个单场工作台，反馈独立 | 采纳信息架构 | 不新增第二套活动状态机；邀请和签到仍保留业务事实，只是不必单独占顶级菜单。 |
| 机会筛选增加城市、发布人、时间和金额，全字段 Excel 导出 | 已有实现 | 现有中立管理契约已提供这些筛选和导出字段。 |
| 只有草稿和招募中的机会可编辑，只有招募中可下架 | 采纳并加固状态机 | 已结束、已下架和已归档保留只读历史。 |

## 不改动或暂缓

- V0.5 的“总部超管 / 城市超管 / 运营管理员”不替换当前七类角色和 capability 模型；这三个名称可作为运营界面上的预设组合。
- “每个城市独立服务器”不改动当前城市分会模型和同 AppID 范围隔离。
- 浏览器多标签用户详情属于未来独立 Web 管理端；当前小程序管理分包继续适配手机和微信电脑端。
- 蓝色侧边栏只是外部 HTML 原型样式，不覆盖 `DESIGN.md` 和 Figma 确定的 MIP 黄/黑视觉。
- 增长值、贡献值对外 Open API 继续暂缓，不为了原型提前扩大攻击面。

## 历史会员数据结论

旧 MIP 研究包和本地旧仓库中没有找到可校验的真实玩家名单、手机号与缴费/权益对应表；旧远程数据源的只读连接也未能返回可验证数据。因此本次不导入任何“历史会员”，也不把 Demo 订单当成真实缴费。后续需要至少提供经授权的手机号标识、订单/缴费事实、权益起止时间和退款/撤销状态，才能通过追加迁移安全导入。
