# MIP 待确认问题

这里只记录会改变产品模型、验收范围或实施路线的问题。纯技术实现细节由工程自行决定。

## 已确认方向（2026-08-25）

### 用户身份

当前已确认规则：拥有有效付费权益的是玩家，其他用户是嘉宾。

不新增第三种会员身份。WorkBuddy 原型中的“普通用户”和“参加早会后变为嘉宾”不进入 MIP 会员状态机；如需区分是否参加过活动，使用活动参与事实或用户历程状态。

### 城市分会

“服务器”是产品 UI 对 MIP 城市分会的习惯称谓，不新增 Server 或通用 Tenant 模型。服务端模型、数据库表和契约继续使用 `branch` / city branch。玩家和嘉宾都可以有一个主分会；会员权益不决定分会归属。

### 运营终端

运营人员可以统一使用 Windows 或 Mac 微信。微信开发者工具最终报告 `.tmp/runtime-evidence/2026-08-28-final-r6/report.json` 已通过 110/110 路由、6/6 代表状态、6/6 交互旅程且 diagnostics 为 0；Mac 和 Windows 微信仍分别保留为发布前兼容性验收，不以开发者工具结果代替。

### 当前交付形态

2026-08-28 更新：保留小程序管理分包，同时增加独立 Web 管理端；该决定由 [ADR 0004](../adr/0004-independent-web-admin.md) 接受，取代此前“独立网页暂缓”的部分。当前 React 生产源码 `c21b3b4` 已部署到 `https://mipmini.01mvp.com/`，Cloudflare Pages deployment ID 为 `22429e0f-344a-49af-8fb8-e76a75f86507`。真实管理员已完成 14/14 个已认证路由的线上只读验收；真实 JPEG 上传、Banner `INACTIVE` 保存与软删除，以及 `USERS`、`includesPhone=false`、唯一无匹配条件的空结果导出均已完成生产闭环。CloudBase 核心及修复函数已部署，`pnpm cloud:verify` 通过。详见[当前 React 生产证据](evidence/admin-web-live-2026-08-28-react/README.md)；此前较小范围的[历史证据](evidence/admin-web-live-2026-08-28/README.md)继续保留。

### 第一条验收闭环

管理端身份、协议、分会权限、响应式壳层和 14/14 路由只读闭环已经通过。活动创建/发布、报名、名单、签到、心动、反馈和审计仍须按各自写入、真机或正式配置边界单独验收，不以 Banner 写入闭环替代。

电脑端负责日常批量运营、长列表、编辑、导出和审计；手机端负责扫码签到、现场处理和快速操作。两端共享业务规则和服务端事实。

## 不阻塞底座、但需在对应切片前确认

### 活动反馈资格

当前内部规则允许所有已签到用户反馈；部分外部描述只允许玩家。推荐所有已签到用户均可反馈。

### 签到现场约束

静态签到海报无法阻止转发。若必须严格现场，需要轮换码或额外现场信号，不能继续把静态二维码描述为“不能远程”。

### 机会发布审核

当前默认只做内容安全，不做人工作前审核。若需人工审核，需要新增待审状态、运营队列和发布延迟规则。

### 玩家权益周期

原型固定一年；当前系统支持可配置会员方案。推荐保留可配置方案，正式目录可只发布一年方案。

### 分会变更的历史归属

原型要求用户迁移后，历史活动、订单、贡献和内容保留原始分会归属。需要确认报表按“发生时分会”还是“当前主分会”统计，推荐同时保留两种维度。

### 仪表盘指标口径

至少需要确认活跃用户、首年/次年续费、机会转化率、互动用户、反馈率和人才库人数的分子、分母、时间窗、去重键和分会归属规则。

### 后台添加手机号用户

原型要求管理员按手机号预建用户并发送短信，用户首次进入小程序后再激活。该流程涉及手机号来源、告知、短信供应商、重复账号合并和未激活数据保留，推荐不进入首版。

### 失败消息重试

原型仍标记待确认。推荐保留批次和单用户失败事实，只对明确可重试错误进行幂等重试，永久错误不自动重试。

## 外部验收等待项（2026-08-28）

- 正式支付、退款回调和会员权益继续以服务端 ledger 为唯一事实；浏览器和开发者工具结果不能替代正式支付验收。
- 手机号授权、扫码签到、订阅消息和小程序文件/相册流程必须真机验证。
- AI/provider 与外部内容安全、采集或生成能力需要正式供应商、配额、错误映射和审计证据；当前不伪造 provider 成功。
- 外部消息投递需要正式通道、收件人快照、回执和失败重试策略；当前只证明站内服务端事实可读。
- Mac 与 Windows 微信客户端仍需分别验证，开发者工具最终 runtime 报告不替代客户端兼容性证据。
- 当前媒体证据只覆盖 Banner 用途真实 JPEG；导出证据只覆盖不含手机号、零行用户结果。其余用途、非空数据和敏感字段仍需最小权限验收。

## 后台 PRD V0.5 边界（2026-08-27）

- 外部文档中的“每个城市独立服务器”不改动城市分会模型；如未来确有合规或负载隔离需求，再单独评审环境拆分。
- 浏览器多标签用户详情归独立 Web 管理端验收；当前用户列表、聚合详情和受控写入口已接入真实 API，不含手机号的零行用户导出已在线通过。该证据不代表全部用户 CRUD 或含敏感字段导出通过。
- React Web 使用 Workbuddy 原型的信息架构和蓝色后台 Design Token；小程序继续使用自己的 MIP 设计规范，两端不共享展示组件。
- 外部提交已包含正式 AppID、CloudBase 环境和商户号线索；是否从当前共享开发环境迁移，仍以正式发布节点和本地密钥配置为准，不把这些标识写入仓库。
- 旧 MIP 当前没有可校验的真实会员导出。若要让历史用户绑定手机号后自动恢复玩家权益，需提供经授权的手机号与订单/权益期限对应表；在此之前不伪造真实缴费。
