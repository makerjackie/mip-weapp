# MIP 待确认问题

这里只记录会改变产品模型、验收范围或实施路线的问题。纯技术实现细节由工程自行决定。

## 已确认方向（2026-08-25）

### 用户身份

当前已确认规则：拥有有效付费权益的是玩家，其他用户是嘉宾。

不新增第三种会员身份。WorkBuddy 原型中的“普通用户”和“参加早会后变为嘉宾”不进入 MIP 会员状态机；如需区分是否参加过活动，使用活动参与事实或用户历程状态。

### 城市分会

原型中的“服务器”统一解释为 MIP 城市分会，不新增 Server 或通用 Tenant 模型。玩家和嘉宾都可以有一个主分会；会员权益不决定分会归属。

### 运营终端

运营人员可以统一使用 Windows 或 Mac 微信。当前先完成 Mac 微信和微信开发者工具验收；Windows 微信保留为发布前兼容性验收，不阻塞当前开发。

### 当前交付形态

2026-08-28 更新：保留小程序管理分包，同时增加独立 Web 管理端；该决定由 [ADR 0004](../adr/0004-independent-web-admin.md) 接受，取代此前“独立网页暂缓”的部分。Web 已部署；既有线上证据覆盖真实管理员确认、33 条只读 action、7 个一级页面和 5 类详情。当前实现已扩展到 62 条只读 action、10 个一级页面和 6 类详情，新增范围已通过本地契约与响应式验证，尚待补录登录后线上读回。补录会员、克隆活动、发布活动提醒和提交退款 4 个受审写操作表单也已部署；其余 CRUD、上传和导出仍属待实现范围。

### 第一条验收闭环

先完成用户管理与免费活动闭环，用它验证身份、协议、分会权限、响应式壳层、活动创建/发布、报名、名单、签到、心动、反馈和审计。该检查点通过后再并行扩展剩余完整范围，不永久裁剪需求。

电脑端负责日常批量运营、长列表、编辑、导出和审计；手机端负责扫码签到、现场处理和快速操作。两端共享业务规则和服务端事实。

## 不阻塞底座、但需在对应切片前确认

### 活动反馈资格

当前内部规则允许所有已签到用户反馈；部分外部描述只允许玩家。推荐所有已签到用户均可反馈。

### 签到现场约束

静态签到海报无法阻止转发。若必须严格现场，需要轮换码或额外现场信号，不能继续把静态二维码描述为“不能远程”。

### 机会发布审核

当前默认只做内容安全，不做人工作前审核。若需人工审核，需要新增待审状态、运营队列和发布延迟规则。

### 玩家权益周期

原型固定一年；当前系统支持可配置会员方案。推荐保留可配置方案，正式目录可只发布一年方案。

### 分会变更的历史归属

原型要求用户迁移后，历史活动、订单、贡献和内容保留原始分会归属。需要确认报表按“发生时分会”还是“当前主分会”统计，推荐同时保留两种维度。

### 仪表盘指标口径

至少需要确认活跃用户、首年/次年续费、机会转化率、互动用户、反馈率和人才库人数的分子、分母、时间窗、去重键和分会归属规则。

### 后台添加手机号用户

原型要求管理员按手机号预建用户并发送短信，用户首次进入小程序后再激活。该流程涉及手机号来源、告知、短信供应商、重复账号合并和未激活数据保留，推荐不进入首版。

### 失败消息重试

原型仍标记待确认。推荐保留批次和单用户失败事实，只对明确可重试错误进行幂等重试，永久错误不自动重试。

## 后台 PRD V0.5 边界（2026-08-27）

- 外部文档中的“每个城市独立服务器”不改动城市分会模型；如未来确有合规或负载隔离需求，再单独评审环境拆分。
- 浏览器多标签用户详情归独立 Web 管理端验收；当前用户列表和聚合详情已接入真实 API，编辑、导出及完整 CRUD 尚未完成。
- 外部 HTML 原型的蓝色侧边栏不替换 MIP 黄/黑品牌系统；后台功能参考其信息架构，视觉继续以 Figma 和 `DESIGN.md` 为准。
- 外部提交已包含正式 AppID、CloudBase 环境和商户号线索；是否从当前共享开发环境迁移，仍以正式发布节点和本地密钥配置为准，不把这些标识写入仓库。
- 旧 MIP 当前没有可校验的真实会员导出。若要让历史用户绑定手机号后自动恢复玩家权益，需提供经授权的手机号与订单/权益期限对应表；在此之前不伪造真实缴费。

## 遗留研究候选（2026-08-27）

以下内容来自旧 mip-app 只读研究包，只能作为可替换默认值或历史对照，尚未形成当前产品决定：

- 行业目录是否采用研究包中的飞书两级行业树，需确认来源表的可访问性、目录维护责任和正式标签范围。
- 城市标签是否补充武汉、中山、香港，超级案例地点是否支持中国香港、中国澳门和海外，需确认业务范围。它们不能自动变成城市分会，也不改变用户只能有一个主分会的规则。
- 档案“身份状态”是否采用 8 选 1 白名单：品牌主理人、专业投资人、大厂精英、在读学生、激情创业者、自由探索者、公司负责人、斜杠青年。该字段不是玩家/嘉宾身份，需确认是否替换当前演示用英文自由文本。
- 六种合作角色是否采用研究包中的中文定位、简介和问卷补充文案，需在保持稳定角色 key 的前提下完成业务和文案确认。
- 当前年度会员基准已确认为 365 天、6000 元，并保持数据库可配置。旧系统的 6600 元和 188 元只保留为历史对照；188 不得新增为用户身份。正式上线前仍需复核方案权益和微信支付商品配置。
- 等级门槛存在两套互相冲突的历史数字，暂不选择：Excel 记录从 Lv.11=17,000 到 Lv.100=12,700,000；旧代码记录从 Lv.11=1,000 到 Lv.100=55,000。需业务确认正式等级数量、门槛和奖励后，才能替换当前三档演示配置；不得据此增加 NPC、笨笨或其他身份/权限。
