## 工作包

### P0 · L3 浏览器 UI 自动化基建（前置）
- 装 Playwright（admin-web devDependency + Chromium）；用 `MIP_ADMIN_TEST_*` 密码登录（无需微信）。
- 新脚本 `scripts/qa/admin-ui-e2e.mjs`：真实点选表单、富文本工具栏（加粗/斜体/下划线/列表/对齐）、封面拖拽、标签胶囊 + 新建弹窗、手机预览弹窗、保存/回读；**抓截图 + 断言 console 无错误**；桌面 1440×900 / 1280×720 与 390×844。
- 纳入“每次部署后我跑”的固定流程；失败即回退。
- 验收：一条命令出通过/失败 + `docs/mip/evidence/.../shots/` 截图。

### P1 · E06 报名与参与人名单（含支付/签到合并）
- 核查后台活动详情「报名与参与人」：用户、报名状态/时间、支付状态、实付金额、签到状态/时间；筛选/搜索/分页/跳用户/跳订单；非空导出（XLSX 真实文件、字段/筛选一致）。
- 支付失败不得显示报名成功；免费不造支付单；补录/取消/异常留原因与审计。
- 双端：小程序参与人页/报名页与后台口径一致。
- 验收：非空 roster 响应 → 页面/导出的合同测试；浏览器 E2E 覆盖；目录/可选请求失败不整页报错。

### P2 · E07 反馈
- 后台独立反馈区：评分、推荐意愿、能力角色、资源、入会意愿、了解方式、花名册意愿、用户、时间；**导出完整反馈**（answers_json）。
- 不删底层邀请/签到事实；不泄漏敏感字段。
- 小程序反馈页与后台口径一致；签到后可填的可见条件确认。
- 验收：反馈列表/导出合同测试 + E2E。

### P3 · E08 签到码与真机
- 后台生成**静态码 + 短时（ROTATING）码**、下载、刷新吊销旧码；二维码有效期与权限。
- 真机扫码（资格/过期/重复/时间/审计）标记真机项，DevTools 不可替代。
- 验收：Web 生成/下载/吊销 E2E；真机项单列。

### P4 · E09 活动统计与下钻
- 活动统计口径（报名/签到/反馈/金额）与下钻，与服务端和最新裁决一致；无数据不假填 0。
- 归属 W16；本轮完成活动范围内的统计呈现与下钻。
- 验收：统计合同测试 + E2E。

### P5 · F03 退款入口缺陷修复
- 已审计：入口投影 `domain/orders.js` 的 `availableRefundActions` 未反映签到/报名状态，导致非超管对已签到单看到必然失败的「提交退款」。
- 修复：**用与服务端事务一致的规则投影可操作性**（已签到且非超管 → 不显示或显示原因）；状态/资格拒绝与网络未知结果分开呈现；弹窗打开后状态变化保留输入并回读。
- 事务侧已由 MIW-108 支持超管例外；本次仅补入口一致性 + 具体原因。
- 验收：`orders` 模块/仓库契约测试（可退/不可退/签到/处理中）+ E2E；真金退款另计。
- 备注：用户报告的具体订单未提供；本轮按**规则一致性**修复，不依赖单号。

## 多 Agent 执行模型

- 并行度：**研究/审计并行，写代码串行或按 worktree 隔离**，避免同文件冲突。
  - Agent A（研究）：W05 服务端/契约全链路审计（roster/feedback/exports/checkin/insights/orders 投影），产出“现状-差距-改动清单”，只读。
  - Agent B（研究）：admin-web W05 页面与模块现状审计（名单/反馈/导出/签到/统计/退款入口），只读。
  - Agent C（实现基建）：Playwright + `admin-ui-e2e`（独立分支 `qa/admin-ui-e2e`）。
  - 之后按 P1→P2→P3→P4→P5 顺序实现（每包：改码 → 本地门禁 → 部署 → L2/L3），避免并行改同文件。
- 冲突控制：每个工作包分支/提交独立；合并前跑完整 `pnpm verify:all`。
- 我负责：改码、门禁、部署、E2E、汇报；你只审报告。
