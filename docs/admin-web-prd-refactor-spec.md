# MIP 管理后台 PRD 对齐重构 Spec

> 生成时间: 2026-09-19
> 访谈参与者: Douglas
> PRD 版本: V0.4（需求细化中）
> 现状基线: admin-web 14 导航页 + 5 独立表单页 + action-based RPC

## 背景与目标

### 问题/需求背景

MIP 管理后台现有 admin-web 已有核心骨架（用户/活动/订单/任务/机会/Banner/成长/权限/消息/运营），但与 PRD v0.4 存在系统性差距：多个模块缺少配置化写入能力、若干整块模块完全缺失、列表筛选和全局 UI 规范未落地。需要按 PRD 补齐缺口，使管理后台覆盖完整运营闭环。

### 项目目标

- 按 PRD v0.4 补齐缺失模块和字段深度，使管理后台功能覆盖率达到 PRD 的 90% 以上
- 保持现有 action-based RPC 架构和 action-based 契约包不变
- 渐进式增量补齐，不推倒重来，现有可用模块保留
- 战队管理和知识内容两个模块暂时搁置，等客户确认需求

### 成功标准

- [ ] P0 模块全部完成并通过 `pnpm admin:web:verify`
- [ ] 任务审批闭环可用（提交→审批→发奖→失败重试）
- [ ] 后台账号管理（阶段 1）上线，审计日志可查
- [ ] 活动反馈数据可查看和导出
- [ ] 权益流水独立模块可查询和手动发放
- [ ] 列表筛选增强覆盖所有列表页
- [ ] 合作卡 6 卡型结构化表单可用
- [ ] `pnpm verify:all` 全绿

## 权衡与决策记录

| 决策点 | 选择 | 原因 | 替代方案 |
|--------|------|------|----------|
| 重构策略 | 增量补齐 | 保留现有架构和可用模块，按 PRD 补齐缺失部分，风险低 | 推倒重来 / 分阶段重建 |
| API 架构 | 保持 action-based RPC | 契约包已基于 action 建立，适合多 section 聚合页面 | 迁移到 RESTful |

| 知识内容 | 暂时搁置 | PRD 未列为独立模块，现状已有实现，需客户确认是否纳入 | 纳入 PRD / 移除 |

| 活动手机端预览弹层 | 保留 | 管理员发布前预览小程序活动详情效果 | 不做 |
| 列表筛选 | 全局统一实现 | 方案 B 开始时间组件 + 金额范围 + 多维度筛选，所有列表页补齐 | 按模块逐步补 |

### FR-001: 任务审批流程

- **描述**: 实现完整的任务提交→审批→奖励发放闭环。8 种任务状态（待开始/进行中/待提交/待审批/已通过/已退回/已过期/奖励失败），笨笨老大审批，通过后一次性发放奖励，退回不发放保留提交内容，奖励失败可重试。
- **验收标准**:
  - [ ] 任务提交后自动进入"待审批"状态
  - [ ] 仅关联的笨笨老大可审批（权限校验）
  - [ ] 审批通过：发放经验值/贡献值/奖金（按任务奖励配置分别启用），幂等不重复发放
  - [ ] 审批退回：填写备注，不发放奖励，保留原提交内容
  - [ ] 奖励失败：记录失败类型和原因，支持有权限的重试
  - [ ] 任务完成流水展示：玩家/任务名+星级/笨笨老大/提交时间/附件/审批结果/实际奖励分项/处理结果
  - [ ] 任务列表新增字段：任务星级（一星–五星）、任务周期（开始/结束/每周交付时间）、关联笨笨老大、奖励内容（经验值/贡献值/奖金分别展示）
- **优先级**: P0
- **依赖**: 任务奖励配置需支持经验值/贡献值/奖金三种分别启用

---

### FR-002: 任务配置增强

- **描述**: 扩展 `tasks.save` 表单字段至 PRD 完整范围。任务奖励配置支持经验值/贡献值/奖金三种类型分别启用或关闭，至少启用一种。
- **验收标准**:
  - [ ] 新增字段：任务星级、任务目的、完成标准、任务周期（开始/结束/每周固定交付时间）、关联笨笨老大、适用服务器
  - [ ] 奖励配置：经验值/贡献值/奖金可分别启用或关闭，未启用不产生对应流水
  - [ ] 奖励用任务提交记录做幂等校验
  - [ ] 回传附件配置是否必须上传
  - [ ] 附件模板支持上传，展示文件名/格式/大小/上传时间，支持在线查看和下载
- **优先级**: P0
- **依赖**: FR-001（审批流程依赖奖励配置）

### FR-003: 每周任务指派

- **描述**: 笨笨老大或有权限的 NPC 账号可派发任务，每个任务必须关联一个笨笨老大，笨笨老大的待分配列表仅展示关联本人的任务。
- **验收标准**:
  - [ ] 支持按用户/角色/服务器/标签选择接收人
  - [ ] 支持单次/批量/每周周期派发
  - [ ] 记录派发人/接收人/派发时间/派发方式/任务版本
  - [ ] 笨笨老大待分配列表仅展示关联本人的任务
- **优先级**: P0
- **依赖**: FR-002（任务需关联笨笨老大）

- **验收标准**:
  - [ ] 账号列表：姓名/登录账号/所属角色/所属服务器/账号状态
  - [ ] 新增账号：姓名/登录账号/手机号/角色/服务器归属；校验登录账号和手机号唯一性
  - [ ] 编辑账号：修改姓名/手机号/角色/服务器归属
  - [ ] 启用/停用/重置登录凭证
  - [ ] 当前登录账号不可停用自身
  - [ ] 最后一个超级管理员不可停用或降权
  - [ ] 账号不做物理删除
  - [ ] 停用后立即禁止登录，保留历史操作记录
- **优先级**: P0
- **依赖**: 无

### FR-007: 权益流水独立模块

- **描述**: 新建权益管理模块，汇总展示经验值/贡献值/玩家会籍的发放流水，支持筛选和手动发放权益。
- **验收标准**:
  - [ ] 权益流水字段：权益流水号/用户 ID/昵称/权益类型（经验值/贡献值/玩家会籍）/权益内容/关联订单号/发放人/发放时间
  - [ ] 不在列表展示发放类型/发放来源/备注
  - [ ] 权益内容：玩家会籍显示"12 个月"/"3 个月"，经验值显示"500 经验值"，贡献值显示具体数值
  - [ ] 用户 ID/昵称/关联订单号可点击进入对应档案或订单详情
  - [ ] 筛选：关键词/权益类型/全局开始时间
  - [ ] 手动发放权益：单个用户，搜索选择用户 ID 或昵称；可选经验值/贡献值/玩家会籍
  - [ ] 经验值和贡献值必须正整数
  - [ ] 玩家会籍默认 12 个月，仅整月时长（1/3/6/12 个月）
  - [ ] 手动会籍不绑定订单，仅追加，不支持撤销/扣回/删除/修改
  - [ ] 系统会籍仅在会费订单支付成功后生成并绑定订单号
- **优先级**: P0
- **依赖**: 无

### FR-008: 列表筛选增强（全局）

- **描述**: 实现全局统一的列表筛选能力，覆盖所有列表页。包括方案 B 开始时间筛选组件、金额范围筛选、多维度下拉筛选、统一分页。
- **验收标准**:
  - [ ] 方案 B 开始时间组件：日期精确到年月日 + 时刻精确到分钟，格式 `YYYY-MM-DD HH:mm`，仅开始时间不筛结束时间，清空恢复全部
  - [ ] 金额范围筛选（机会管理）：最小值和最大值输入，单位万元
  - [ ] 用户列表筛选：行业/当前身份/玩家权益状态/时间类型选择（注册时间或到期时间）+ 开始时间/服务器切换/关键词
  - [ ] 活动列表筛选：开始时间/费用金额/活动标签/服务器（城市）
  - [ ] 机会列表筛选：状态/主营城市/发布人（datalist + 昵称搜索）/发布时间（本周/本月/自定义区间）/价值金额范围/关键词
  - [ ] 订单列表筛选：订单号/玩家 ID/手机号/订单类型/状态/服务器/时间
  - [ ] 统一分页：10/20/50/100 条每页 + 跳转页码
  - [ ] 用户/订单列表支持导出当前筛选结果
- **优先级**: P0
- **依赖**: 无

## 非功能性需求

### 性能

- **响应时间**: 列表页加载 < 2s，API 响应 < 500ms（不含导出）
- **数据量**: 用户 ~10 万级，订单 ~100 万级，列表分页查询不退化
- **导出**: 异步四步工作流（create→prepare→reserve→complete），不阻塞 UI

### 安全

- **认证**: 手机验证码登录（现有），阶段 2 增加密码登录
- **授权**: capability + scope 模型（现有），按服务器数据权限隔离
- **数据保护**: 手机号脱敏展示，敏感导出需四步工作流 + SHA256 校验
- **审计**: 操作审计日志不可编辑或删除

### 兼容性

- **浏览器**: Chrome/Edge/Firefox 最新版（桌面端），不考虑手机端适配
- **API 版本**: 保持 contractVersion 1，action-based RPC 向后兼容

## 技术方案

### 架构设计

保持现有架构不变：

```
React 19 + TanStack Router (hash) + TanStack Query + Ant Design 6 + Vite
    ↓
AdminApiClient → 单一 POST /api/admin（action-based RPC）
    ↓
契约包 @mip/admin-contracts（action 清单 + input/output 类型）
    ↓
同源 BFF → mip-admin-api
```

新增模块按现有模式实现：
- 列表页：`useAdminReadPage` + `AdminReadPage` 多 section 装载
- 详情抽屉：`admin-details.ts` 新增 detail route
- 表单：`MutationDialog`（对话框）或 `IndependentFormPage`（独立页）
- 写操作：`OperationField[]` 定义 → `buildInput` 校验 → `request(action, input)`

### 数据模型

#### 合作卡 6 卡型（新增）

```
CooperationCard {
  userId: string
  cardType: 'PIMP' | 'BUSINESS' | 'RICH' | 'PLANNER' | 'DESIGNER' | 'NANNY'
  // 共同字段
  gameName: string
  targetSummary: text          // 我的目标
  referralNeeded: text         // 需要引荐的是
  quirks: text                 // 臭毛病（外显）
  rootCause: text              // 病因（内在）
  prevention: text             // 预防发作建议
  cooperationValue: text       // 和我合作最大的价值
  // 特征评分（每种卡型 6 项，1-5 星）
  abilityScores: { key: string, score: 1-5 }[]
  // 菜单字段（按卡型不同）
  menuFields: Record<string, any>
  status: 'ACTIVE' | 'INACTIVE'
  // 审计
  modifiedBy: string
  modifiedAt: datetime
}
```

卡型与评分项映射：
- PIMP（皮条客）: 开拓人脉/引荐人脉/长期维护/引荐商机/卖点提炼/跨圈交际
- BUSINESS（生意佬）: 商机洞察/财务测算/盈利建模/资源整合/利益统筹/合作谈判
- RICH（暴发户）: 投资洞察/上市规划/股权规划/投融策划/融资达成/资源整合
- PLANNER（狗策划）: 项目调研/项目定位/创新创意/方法设计/提案竞标/落地规划
- DESIGNER（死美工）: 视觉策略/视觉设计/素材搜寻/视觉落地/视觉管理/提案竞标
- NANNY（老保姆）: 目标计划/执行统筹/进度复盘/沟通机制/标准研发/应急沟通


## 边界条件与异常处理

| 场景 | 处理策略 |
|------|----------|
| 任务奖励重复发放 | 用任务提交记录做幂等校验，不重复发放 |
| 经验值冲正后小于 0 | 冲正后重算，不得造成用户经验值小于 0 |
| 权益手动会籍撤销 | 手动会籍仅追加，不支持撤销/扣回/删除/修改 |
| 重复支付回调 | 不得重复更新权益或发放业务结果 |
| 会费订单退款 | 不支持退款，不展示退款入口 |
| 活动开始后退款 | 提示"活动已开始，暂不支持退款" |
| 后台账号停用自身 | 当前登录账号不可停用自身 |
| 最后一个超级管理员 | 不可停用或降权 |
| 合作卡重复发放 | 已拥有默认选中不重复发放 |
| Banner 超 5 个 | 提示"Banner 最多添加 5 个"，不可保存 |
| 贡献规则冲突 | 同一行为在相同时间和服务器范围内不可存在冲突规则 |
| 版本冲突 | expectedVersion 乐观锁，冲突时保留草稿提示重新打开 |
