# 影响力统计合同

“我的”和公开档案使用同一套服务端聚合。客户端只展示整数结果；接口未返回某项时显示 `—`，不得用本地列表长度、缓存或示例数据补值。

## 统计口径

| 指标 | 单一口径 | 列表 |
| --- | --- | --- |
| 嘉宾 | 由本人作为 `USER` 邀请来源，当前报名为 `ATTENDED` 且有有效签到、同意公开资料，且查询时没有有效会员权益的去重用户数 | 每位当前嘉宾一条，按最近一次有效签到时间倒序，并显示最近活动和已签到邀请次数 |
| 互动 | 双方在同一活动拥有有效签到且报名为 `ATTENDED` 的去重用户数 | 每人一条；服务端返回全部同场次数 `interactionCount`，多次显示 ×N；按最近一次签到时间倒序，支持公开姓名、行业、简介搜索 |
| 感兴趣 | 其他有效用户对本人建立的当前 `ACTIVE` 档案兴趣关系数 | 每个当前关系一条，按更新时间倒序 |
| 访客 | 当前仍有效且可见的档案访问操作次数 | 每次访问一条，同一天访问两次显示两条，按访问时间倒序；卡片不显示时间，无搜索框 |

“玩家”只由查询时有效的 `mip_membership_entitlements` 投影；其余有效用户为“嘉宾”。会员到期、退款或撤销后，嘉宾口径随服务端当前事实变化。引荐机会属于机会关系，不并入“互动”。主页总浏览量和“访客”均按可见访问操作累计；不使用客户端已加载卡片数推算。活动“心动值”单独读取 `mip_event_hearts` 当前有效投票，和档案“感兴趣”关系分开；“我的心动 / 对我心动”两页签只查看，投票及取消仍在原活动内操作。

## 服务边界

- 本人汇总通过 `mip-opportunities-api.getProfileInfluence` 获取；调用前由服务端解析当前 `ACTIVE` 用户，客户端不提交用户 ID。
- 四类列表复用 `listReceivedInteractions` 的 `GUEST`、`INTERACTION`、`ACTIVE_INTEREST`、`VISITOR` 分类。分页游标不含明文用户 ID。
- 公开档案聚合只在档案所有者显式设置 `visibility.influence === true` 时返回 `influence`。历史资料缺少该字段时按未公开处理；关闭后整个字段省略，页面显示 `—`。
- 2026-09-22 J4-02b：玩家可从他人档案的「+N 感兴趣」进入「对TA感兴趣」名单；服务端检查当前有效会员权益、档案 `visibility.influence === true` 及查看者与档案所有者双向屏蔽。其他三类身份列表仍只向本人开放。
- `listPublicProfileInterests` 按关系更新时间从新到旧分页，游标只包含 opaque `profileRef`。感兴趣聚合数与名单共用当前有效关系、档案所有者/查看者双向屏蔽过滤；昵称、头像、简介逐字段遵守公开设置，分页失败保留已经加载的正文。
- 聚合与列表均限定同一 `app_id`，过滤已关闭账号、没有可展示档案的人员和任一方向的有效屏蔽关系。访问事实只有在访客当前仍是同 AppID 的 `ACTIVE` 用户且存在可展示档案时才进入列表、总量和未读统计。相关人员姓名、头像和简介继续分别遵守其公开资料可见性；普通 DTO 只返回 AppID 绑定的 opaque `profileRef`，不返回内部用户 ID、OpenID、手机号或报名答案。
- 嘉宾列表额外要求报名人选择 `share_profile=1`。没有可证明的现有事实时只返回 `0` 或省略整个汇总，不推断邀请、互动、兴趣或访问。

影响力聚合权威查询位于 `cloudfunctions/mip-opportunities-api/domain/profile-influence.js`；活动心动及阅读水位位于 `cloudfunctions/mip-events-api/domain/event-service.js`。迁移 `083_event_heart_read_state.sql` 为心动接收方补充阅读时间及索引，并为同场签到查询补充用户索引。

“我的”访客入口以标签右上角红点提示有未读访客。访客列表成功展示后，按服务端返回的 `readThroughAt` 水位将进入前全部访问记录标为已读（包含尚未翻页的记录）；后台预加载、隐藏页面和加载失败不算已读。服务端确认后更新未读提示，失败保留提示并支持刷新重试；水位之后的新访问不受影响。

批量访客已读审计的 `resource_id` 使用当前档案所有者 UUID；兼容旧版逐人标记时使用服务端解析的访客用户 UUID。公开 `profileRef` 只保存在审计 metadata，不能写入 `CHAR(36)` 资源字段。刷新失败时保留正文，重试过程显示进度并防止重复提交。

公开档案、机会和合作卡的“感兴趣”共享乐观更新状态：点击后立即显示最新选择，连续切换由同一队列顺序提交。正常请求不显示同步文案或锁住兴趣按钮；明确拒绝时回滚并提示，网络结果不确定时保留意图和幂等键、提示重新进入页面恢复，不能把未知结果当作服务端成功。

心动值入口和“对我心动”标签只显示红点，不显示数字角标；“我的心动”无未读点。进入心动页且正文成功展示即按服务端阅读水位清除进入前全部收到的心动。仅查询汇总、页面隐藏或列表失败不会标记已读。标记只允许更新调用者收到的记录，并保留投票 `updated_at`，不会改变列表排序或投票版本；重新投票重置接收方已读状态。
