# MIP 管理后台 PRD v0.4 差异分析

> 对比文件：`MIP 小程序后台管理系统 PRD - v1.html`（V0.4，2026-09 状态：需求细化中）
> 现状基线：`admin-web/` 当前代码（14 导航页 + 5 独立表单页 + action-based RPC）

结论先行：现有 admin-web 已覆盖 PRD 约十六个模块中的**核心骨架**（用户/活动/订单/任务/机会/Banner/成长/权限/消息/知识/运营/战队），但在**细节深度、完整业务闭环、若干整块模块和全局 UI 规范**上与 PRD 存在显著差距。PRD 把很多"子模块"当成独立管理对象（合作卡 6 型、超级案例、名片、经验值规则与流水、贡献值规则与流水、权益流水、等级权益、签到码与统计、审计日志、后台账号、登录记录、角色权限配置、服务器、视频回顾），而现状大多只有"读 + 轻量写"，缺少配置化和流水化管理。

---

## 一、功能需求差异

### 1. 全局约定（现状缺失）

| PRD 要求 | 现状 | 差距 |
|---|---|---|
| 统一开始时间筛选组件（方案 B）：日期 + 时刻精确到分钟，仅开始时间，清空恢复全部 | `FilterBar` 只支持 `q`+`status`，时间筛选未实现 | 列表筛选层缺时间筛选组件 |
| 统一分页 10/20/50/100 + 跳页 | 分页器存在，但 `pageSize` 选项未对齐到 PRD 枚举 | 需统一分页选项 |
| 金额范围筛选（最小/最大，万元） | 机会列表无金额范围筛选 | 缺金额范围筛选控件 |
| 多标签页（顶部可开/关） | 无顶部多标签页 | 缺标签页管理 |
| 消息铃铛 + 未读 badge | 无 | 缺全局通知 |
| 当前账号弹层（姓名/手机号/角色/服务器/退出） | 有登录态，但无此类弹层 | 缺账号信息弹层 |

## 二、API 需求差异

### 架构层面

| 维度 | PRD 隐含 | 现状 | 差距 |

## 三、优先级建议

### P0（核心业务闭环缺失，影响日常运营）

1. **任务审批流程**（approve/reject/retry）—— NPC 任务闭环当前断在审批
2. **活动反馈子模块** —— 反馈数据完全无法查看
3. **经验值/贡献值规则配置 + 冲正** —— 成长体系无法配置化
4. **权益流水 + 统一发放入口** —— 权益发放无审计
5. **后台账号管理 + 登录记录 + 审计日志完整页** —— 安全合规基础
6. **列表筛选增强**（时间/多维度/金额范围）—— 全局通用能力

### P1（重要功能补全）

7. **合作卡 6 卡型结构化** —— 核心业务卡片深度
8. **用户档案数据看板**（8 项影响力指标）
9. **机会操作记录 + 删除**
10. **活动签到二维码 + 数据统计下钻**
11. **角色权限配置化**（菜单权限/操作权限/角色 CRUD）
12. **视频回顾模块**
13. **名片管理**

### P2（体验优化）

14. 手机端活动预览弹层
15. 草稿自动恢复
16. 多标签页 + 消息铃铛
17. 全局开始时间筛选组件
18. 导出扩展到更多模块
19. 战队模型与 PRD 对齐（固定 9 团队 vs 赛季制）—— 需产品决策

### 待产品决策

- 战队模型：现状赛季/盲盒体系 vs PRD 固定 9 团队 + 大本营
- 知识内容：现状已有但 PRD 未列，是否纳入
- API 架构：保持 action-based RPC vs 迁移 RESTful（推荐保持 RPC）
- PRD 待确认项：权益是否需业务校验、取消报名退费规则、登录失败限制、消息失败重试
