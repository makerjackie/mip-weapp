# M03 活动管理增强

> 来源: [admin-web-prd-refactor-spec.md](../admin-web-prd-refactor-spec.md) FR-006 / FR-015 / FR-016 / FR-017 / FR-018
> 模块编号: M03
> 模块名称: 活动管理增强
> Wave: 1（FR-006, FR-015, FR-017, FR-018 独立可并行）+ 2（FR-016 依赖 FR-006）
> 现状基线: `admin-web/src/modules/admin-event-mutation-forms.ts`（10 个活动 mutation action）+ `admin-web/src/modules/admin-details.ts` 的 `loadEventDetail`（含活动信息 / 参与情况 / 互动数据 / 财务数据 / 反馈数据 / 报名名单 / 待审核相册 section）

## 现状与差距

### 现状

- 活动保存表单 `mip.admin.events.save` 已覆盖基础字段（范围 / 名称 / 摘要 / 介绍 / 封面 / 时间 / 地点 / 价格 / 报名字段 schema 等）。
- 活动详情 `loadEventDetail` 通过 `mip.admin.events.insights.get` 装载参与情况 / 互动 / 财务 / 反馈汇总指标，反馈仅展示「已提交 / 可提交签到 / 提交率 / 已评分 / 平均评分」5 个聚合指标，无法查看反馈明细。
- 报名审核 / 签到 / 撤销签到 / 相册审核 / 标签替换 / 目录管理 action 已存在。
- 反馈作为独立子模块、签到二维码下载、手机端预览弹层、报名补录 / 取消 / 标记异常均缺失。
- `events.insights.get` 现状字段不足以支撑 FR-016 的下钻需求（缺少访问量 / 分享量 / 心动明细等）。

### 差距

| 差距 | 关联 FR |
|------|--------|
| 反馈仅聚合指标，无明细列表与导出 | FR-006 |
| 无签到二维码生成与下载 | FR-015 |
| 统计字段不全，无心动明细与下钻筛选 | FR-016 |
| 无手机端预览弹层 | FR-017 |
| 报名仅支持审核与签到，无补录 / 取消 / 标记异常 | FR-018 |

## Wave 1 — 独立可并行

### FR-006: 活动反馈子模块

- **描述**: 活动详情新增独立反馈子模块（不并入参与人列表），查看全部反馈内容和数据导出。反馈子模块与「报名名单」「待审核相册」平级，作为活动详情的独立 section。
- **验收标准**:
  - [ ] 活动详情新增独立「活动反馈」section，不并入参与人列表
  - [ ] 反馈字段完整展示：本次活动体验评分 / 是否推荐 MIP / 符合的能力角色（多选）/ 可促成合作或引荐的资源（选填）/ 是否有意愿加入 MIP / 深入了解方式（多选）/ 是否愿意加入花名册
  - [ ] 查看全部反馈内容 / 反馈用户 / 提交时间
  - [ ] 反馈列表支持分页（复用统一分页 10/20/50/100）
  - [ ] 支持下载全部反馈数据（走异步四步导出工作流：create → prepare → reserve → complete，不阻塞 UI）
  - [ ] 反馈数据权限继承活动财务 / 反馈数据的 `access !== 'GRANTED'` 时显示「当前账号不可查看」，与现有 `feedbackSection` 权限判断一致
  - [ ] 反馈用户为空或字段未填写时显示「—」，不报错
  - [ ] 导出文件含 SHA256 校验，敏感字段（手机号等）按现有脱敏规则处理
- **新增 API action**:
  - `mip.admin.events.feedbacks.list` — 反馈列表，入参 `{ eventId, cursor?, limit?, filters? }`，出参 `{ items, nextCursor }`
  - `mip.admin.events.feedbacks.export` — 反馈导出，接入异步四步工作流
- **契约扩展**: `packages/admin-contracts` 新增上述 action 的 input/output 类型与 action 清单条目。
- **数据库迁移**: 反馈明细查询基于现有反馈表，无需新建表；如反馈字段（能力角色多选 / 深入了解方式多选等）未持久化，需追加迁移补齐字段。
- **依赖**: 无（消费 M01 的列表筛选组件用于反馈列表筛选）。
- **优先级**: P0

### FR-015: 活动签到二维码

- **描述**: 每场活动生成唯一签到二维码，支持在活动列表直接下载。已报名用户扫码直接签到，防重复签到。
- **验收标准**:
  - [ ] 每场活动生成唯一签到二维码（按 eventId 派生，活动版本变更不换码）
  - [ ] 支持在活动列表行操作直接下载二维码图片
  - [ ] 活动详情页提供「下载签到二维码」入口
  - [ ] 已报名用户扫码直接签到，服务端校验报名状态与签到幂等
  - [ ] 防重复签到：已签到记录再次扫码提示「已签到」，不重复记录
  - [ ] 记录签到时间 / 签到状态 / 操作日志（扫码签到 / 后台确认签到 / 撤销签到）
  - [ ] 二维码下载不需要财务数据权限，仅需 `events.checkin.manage` 或 `events.write` 能力
  - [ ] 二维码内容为小程序签到页路径 + 活动标识，不得包含可伪造的签到确认参数
- **新增 API action**:
  - `mip.admin.events.checkinQrcode.get` — 入参 `{ eventId }`，出参 `{ qrCodeAssetId, downloadUrl, format, generatedAt }`
- **契约扩展**: 新增 action 类型定义；复用现有 `events.checkIn` / `events.undoCheckIn`。
- **数据库迁移**: 若签到二维码素材需持久化关联，追加迁移记录 `event_checkin_qrcode`（eventId / assetId / generatedAt）；否则运行时生成即可。
- **依赖**: 无。
- **优先级**: P1

### FR-017: 活动手机端预览弹层

- **描述**: 管理员在创建 / 编辑活动时，点击「预览」以手机尺寸弹层展示小程序活动详情页效果。预览不产生任何业务数据。
- **验收标准**:
  - [ ] 活动编辑表单（`mip.admin.events.save` 的 IndependentFormPage 或 MutationDialog）新增「预览」按钮
  - [ ] 点击「预览」以手机尺寸弹层（约 375px 宽）展示小程序活动详情页
  - [ ] 展示字段：封面 / 标签 / 活动名称 / 起止时间 / 场地文案 / 费用金额 / 参与人 / 活动介绍 / 主办方介绍 / 报名须知 / 报名按钮
  - [ ] 图文按手机端实际宽度排版（活动介绍媒体按手机端宽度等比缩放，不按桌面宽度展示）
  - [ ] 预览数据来源为当前编辑表单的未保存草稿值，不要求先保存
  - [ ] 预览不产生报名 / 支付 / 发布数据，不调用任何写 action
  - [ ] 报名按钮在预览中为禁用态或点击仅提示「预览模式不可报名」
  - [ ] 可关闭弹层返回编辑，关闭后表单已填内容保留
  - [ ] 预览弹层为纯前端组件，不新增服务端 action
- **依赖**: 无。复用现有活动表单字段定义（`eventSaveFields`）渲染预览。
- **优先级**: P1

### FR-018: 活动报名与支付联动增强

- **描述**: 补齐报名管理操作，支持补录 / 取消 / 标记异常报名，并明确报名与支付的联动规则。
- **验收标准**:
  - [ ] 免费活动（`accessType === 'FREE'`）直接报名不产生支付订单
  - [ ] 付费活动（`accessType === 'PAID'`）支付成功后才生成成功报名记录
  - [ ] 支付失败不得生成成功报名（报名状态保持「待支付」或回退至可重试状态，不进入「已报名」）
  - [ ] 同一用户不可重复报名同一活动（服务端幂等校验，前端提示「已报名该活动」）
  - [ ] 支持后台补录报名：选择用户 / 角色标记（普通用户 / 嘉宾 / 玩家），补录不触发支付
  - [ ] 补录报名记录来源标记为「后台补录」，记录操作人 / 操作时间
  - [ ] 支持取消报名：填写取消原因，记录操作人 / 操作时间；付费活动取消按现有退款规则处理（不在本 FR 重新定义退费规则）
  - [ ] 支持标记异常报名：填写异常原因，报名状态置为「异常」，不影响签到与名单统计的口径由服务端决定
  - [ ] 补录 / 取消 / 标记异常均需 `events.registrations.manage` 能力，并写入审计日志
  - [ ] 报名名单行操作扩展「补录」「取消」「标记异常」入口（与现有「审核」「签到」「撤销签到」并列）
- **新增 API action**:
  - `mip.admin.events.participants.import` — 后台补录报名，入参 `{ eventId, userId, roleMark?, reason? }`
  - `mip.admin.events.participants.cancel` — 取消报名，入参 `{ eventId, registrationId, expectedVersion, reason }`
  - `mip.admin.events.participants.markAbnormal` — 标记异常，入参 `{ eventId, registrationId, expectedVersion, reason }`
- **契约扩展**: 新增 3 个 action 类型定义；扩展 `EVENT_MUTATION_ACTIONS` 与 `EVENT_MUTATION_CONFIGS`。
- **数据库迁移**: 报名记录如需「异常」状态或「后台补录」来源标记，追加迁移补齐字段；不得直接改现有报名表结构。
- **依赖**: 无。
- **优先级**: P1

## Wave 2 — 依赖 Wave 1

### FR-016: 活动数据统计下钻

- **描述**: 扩展活动统计，补齐 PRD 要求的全部统计字段和下钻能力。依赖 FR-006 的反馈明细数据源。现状 `events.insights.get` 部分字段已有，需扩展。
- **验收标准**:
  - [ ] 统计字段完整：访问量 / 分享量 / 邀请人数 / 报名人数 / 付费人数 / 实付金额 / 签到人数 / 签到率 / 反馈人数 / 反馈率 / 平均评分
  - [ ] 统计普通用户 / 嘉宾 / 玩家人数（在现有 `composition.playerCount` / `guestCount` 基础上补齐普通用户数）
  - [ ] 统计心动次数和双向心动数（扩展现有 `hearts.activeVoteCount` / `mutualMatchCount`，补充总心动次数）
  - [ ] 支持查看心动明细：谁向谁 / 关联活动 / 发生时间 / 关系状态
  - [ ] 心动明细分页加载，复用统一分页
  - [ ] 支持按活动 / 城市 / 服务器 / 时间筛选并下钻
  - [ ] 下钻入口：统计指标卡片可点击进入对应明细列表（如点击「反馈人数」进入 FR-006 的反馈列表）
  - [ ] 反馈率 = 反馈人数 / 签到人数，签到率 = 签到人数 / 有效报名人数，分母为 0 时显示「—」不报错
  - [ ] 数据权限不足时（`access !== 'GRANTED'`）显示「当前账号不可查看」，与现有 `financialSection` / `feedbackSection` 权限判断一致
  - [ ] 扩展后的 `events.insights.get` 出参向后兼容，现有 `loadEventDetail` 的参与情况 / 互动 / 财务 / 反馈 section 不破坏
- **新增 API action**:
  - `mip.admin.events.hearts.list` — 心动明细列表，入参 `{ eventId, cursor?, limit?, filters? }`，出参 `{ items, nextCursor }`
- **契约扩展**: 扩展 `events.insights.get` 出参类型（新增 visitCount / shareCount / heartTotalCount 等字段）；新增 hearts.list action。
- **数据库迁移**: 访问量 / 分享量如未持久化，追加迁移补齐事件访问与分享记录表；心动明细基于现有心动关系表查询。
- **依赖**: FR-006（反馈数据源，反馈率 / 反馈人数 / 平均评分来自反馈子模块）。
- **优先级**: P1

## 边界条件与异常处理

| 场景 | 处理策略 |
|------|----------|
| 重复支付回调 | 不得重复生成成功报名或重复发放业务结果（服务端幂等） |
| 同一用户重复报名同一活动 | 服务端拒绝，前端提示「已报名该活动」 |
| 支付失败的付费活动报名 | 不进入「已报名」状态，保持「待支付」或可重试 |
| 已签到用户再次扫码签到 | 提示「已签到」，不重复记录签到时间 |
| 预览弹层中点击报名按钮 | 禁用或提示「预览模式不可报名」，不调用任何写 action |
| 反馈字段未填写 | 显示「—」，不报错 |
| 反馈 / 财务数据权限不足 | 显示「当前账号不可查看」，与现有 section 权限判断一致 |
| 签到率 / 反馈率分母为 0 | 显示「—」，不报除零错误 |
| 补录报名的用户已报名 | 服务端拒绝重复补录，提示「该用户已报名」 |
| 取消 / 标记异常缺原因 | 前端校验拦截，不发起请求 |
