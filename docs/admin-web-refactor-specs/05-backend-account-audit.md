# M05 后台账号与审计

> 来源: [admin-web-prd-refactor-spec.md](../admin-web-prd-refactor-spec.md)
> 模块: M05 后台账号与审计
> Wave: 1（FR-004 → FR-005）+ Wave 2（FR-026，依赖 FR-004 完成）
> FR 覆盖: FR-004 后台账号管理（阶段 1）、FR-005 审计日志独立页、FR-026 后台账号管理（阶段 2）
> 预估复杂度: 中

## 1. 模块定位

补齐 admin-web 在后台账号管理、审计日志查询、角色权限配置化三块的能力缺口。现状仅有用户级 `roles.set` / `rolePolicies.update` 写操作和 permissions 页内的"审计记录" section 快捷预览，缺少独立的账号管理对象、独立审计日志查询页、阶段 2 的密码登录、登录记录和角色配置化能力。

本模块分两个 Wave：

- **Wave 1**：先上账号管理（阶段 1）和审计日志独立页，让运营可以在后台直接管理后台账号并查询完整审计记录。阶段 1 暂用现有手机验证码登录，不动登录通道。
- **Wave 2**：待 FR-004 完成后启动阶段 2，补齐密码登录、登录记录和角色权限配置化。

## 2. 依赖关系

| FR | 依赖 | 说明 |
|----|------|------|
| FR-004 | 无 | 阶段 1 账号管理可立即启动 |
| FR-005 | FR-004 | 审计日志独立页依赖账号管理提供操作者信息（操作者姓名/角色/服务器归属来自账号对象） |
| FR-026 | FR-004 | 阶段 2 密码登录、登录记录、角色配置化建立在阶段 1 账号模型之上 |

### 跨模块依赖

- **消费 M01（列表筛选增强）**：审计日志独立页和登录记录页的筛选复用 M01 的方案 B 开始时间组件、多维度下拉筛选和统一分页。M01 完成后接入。
- 不与其他业务模块产生数据耦合。

## 3. 现状基线

参考代码：

- `admin-web/src/modules/admin-people-mutation-forms.ts`：现有 `mip.admin.roles.set`（按用户设置运营角色，`roleKey` + `scopeId` + `branchId` + `active`）和 `mip.admin.rolePolicies.update`（按角色更新能力清单 `capabilities` + `reset`）。两者都挂在 permissions 页的"运营成员"/"角色策略" section 上，是对用户施加角色，不是独立的账号对象。
- `admin-web/src/features/governance-pages/governance-pages.tsx`：permissions 页 sections 为 `members` / `policies` / `branches` / `audit`。"审计记录" section 仅做快捷预览，无独立查询页。
- `admin-web/src/app/session-provider.tsx`：会话以 `AdminSession` + `capabilities` 表达，`hasCapability` / `hasCapabilityAtScope` 做权限判断；登录走 `beginLogin` → `pollLogin` 的微信网页登录流程，无密码登录通道。

阶段 1 不替换以上机制，新增独立的"后台账号"管理对象和"审计日志"查询页；阶段 2 才扩展登录通道和角色配置化。

## 4. Wave 1 — FR-004 后台账号管理（阶段 1）

### 4.1 账号列表

- [ ] 列表字段：姓名 / 登录账号 / 所属角色 / 所属服务器 / 账号状态
- [ ] 账号状态展示为标签：启用 / 停用
- [ ] 复用 M01 统一分页（10/20/50/100 条每页 + 跳转页码）
- [ ] 仅展示有 `audit.read` 或 `roles.change` 能力的账号可被当前登录账号查看（按服务端返回为准，前端不自行过滤）

### 4.2 新增账号

- [ ] 表单字段：姓名 / 登录账号 / 手机号 / 角色 / 服务器归属
- [ ] 登录账号在系统内唯一，重复时表单报错"登录账号已存在"
- [ ] 手机号在系统内唯一，重复时表单报错"手机号已被使用"
- [ ] 角色从现有 `ROLE_OPTIONS` 枚举选择（`PLATFORM_OWNER` / `PLATFORM_OPERATIONS` / `PLATFORM_FINANCE` / `BRANCH_ADMIN` / `EVENT_OWNER` / `EVENT_MANAGER` / `EVENT_STAFF`），与 `mip.admin.roles.set` 的 `roleKey` 取值一致
- [ ] 服务器归属为 `BRANCH_ADMIN` 或 `EVENT_*` 角色时必填，与 `mip.admin.roles.set` 的 `scopeId` / `branchId` 规则对齐
- [ ] 新建账号默认启用状态

### 4.3 编辑账号

- [ ] 可修改字段：姓名 / 手机号 / 角色 / 服务器归属
- [ ] 登录账号创建后不可修改（仅展示）
- [ ] 手机号修改时重新校验唯一性
- [ ] 角色变更时校验服务器归属是否仍必填

### 4.4 启用 / 停用 / 重置登录凭证

- [ ] 启用操作：将停用账号恢复为启用
- [ ] 停用操作：将启用账号停用
- [ ] 重置登录凭证：重置当前账号的登录凭证（阶段 1 下发新的验证码登录态令牌，阶段 2 扩展为重置密码）
- [ ] 以上三个操作均记录审计日志（操作者 / 被操作账号 / 操作类型 / 时间 / 原因）

### 4.5 安全保护规则

- [ ] 当前登录账号不可停用自身：前端隐藏/禁用自身的"停用"操作，服务端二次校验
- [ ] 最后一个超级管理员（`PLATFORM_OWNER` 且启用状态）不可停用或降权：服务端拒绝并返回明确原因
- [ ] 账号不做物理删除：列表不提供删除入口，停用即等同下线
- [ ] 停用后立即禁止登录：停用账号的会话在下次请求时被服务端拒绝（`AUTH_REQUIRED`），前端 `SessionProvider` 的 `commitSession(null)` 流程接管

### 4.6 登录通道

- [ ] 阶段 1 暂用现有手机验证码登录（`AdminApiClient.beginLogin` / `pollLogin` 流程不变）
- [ ] 新建账号后由运营线下告知登录方式，本期不在系统内下发初始密码

## 6. Wave 2 — FR-026 后台账号管理（阶段 2）

> 启动条件：FR-004 阶段 1 完成并通过验收。

### 6.1 密码登录

- [ ] 支持手机号验证码 + 手机号密码双登录方式
- [ ] 登录页提供两种登录方式切换
- [ ] 密码登录走新增 action，不破坏现有 `beginLogin` / `pollLogin` 验证码流程
- [ ] 密码相关凭证不在前端持久化，不在日志/请求 URL 中出现

### 6.2 登录记录

- [ ] 登录记录字段：登录账号 / 登录时间 / 登录结果 / IP 地址 / 设备信息 / 失败原因
- [ ] 支持按账号筛选
- [ ] 支持按登录结果筛选（成功 / 失败）
- [ ] 支持按时间筛选：复用 M01 方案 B 开始时间组件
- [ ] 复用 M01 统一分页
- [ ] 失败原因对运营可见，用于排查异常登录

### 6.3 角色配置

- [ ] 角色字段：角色名称（唯一）/ 角色说明 / 菜单权限 / 操作权限 / 数据权限 / 角色状态
- [ ] 操作权限枚举：查看 / 新增 / 编辑 / 删除 / 发布 / 下架 / 导出
- [ ] 数据权限：全部服务器 或 指定服务器（多选）
- [ ] 角色状态：启用 / 停用
- [ ] 角色名称在系统内唯一，重复时报错"角色名称已存在"

### 6.4 角色操作

- [ ] 新增角色
- [ ] 查看角色详情
- [ ] 编辑角色
- [ ] 复制角色（基于现有角色复制一份新角色，名称需重新填写并校验唯一）
- [ ] 启用 / 停用角色
- [ ] 角色操作走新增 roles CRUD action，与现有 `rolePolicies.update`（按角色更新能力清单）区分：`rolePolicies.update` 仍保留用于按角色微调能力，roles CRUD 用于完整的角色对象管理

### 6.5 安全保护规则

- [ ] 超级管理员角色拥有全部权限，不允许普通管理员修改或停用
- [ ] 超级管理员角色的菜单权限/操作权限/数据权限不可被编辑
- [ ] 已绑定账号的角色不允许删除，仅允许停用（停用后已绑定账号的权限随角色停用）
- [ ] 角色不做物理删除（与账号管理一致），停用即等同下线

### 6.6 权限变更同步生效

- [ ] 角色权限变更后，对已绑定该角色的账号同步生效
- [ ] 同步生效在下次受影响账号的请求中被服务端校验（不要求前端主动刷新所有会话）
- [ ] 当前登录账号自身权限被调整时，`SessionProvider` 的 `sessionBoundary` 机制触发受保护查询缓存失效

### 6.7 连续登录失败限制

## 7. 新增 API action

### 7.1 FR-004 阶段 1（Wave 1）

| action | 说明 | 输入要点 | 输出要点 |
|--------|------|----------|----------|
| `mip.admin.adminAccounts.list` | 账号列表 | 分页 + 筛选（角色/服务器/状态/关键词） | 账号行（姓名/登录账号/角色/服务器/状态/版本） |
| `mip.admin.adminAccounts.create` | 新增账号 | 姓名/登录账号/手机号/角色/服务器归属 | 账号 ID |

| `mip.admin.adminAccounts.changeStatus` | 启用/停用 | 账号 ID + expectedVersion + status + 原因 | 更新结果 |
| `mip.admin.adminAccounts.resetCredential` | 重置登录凭证 | 账号 ID + 原因 | 重置结果 |

### 7.2 FR-005 阶段 1（Wave 1）

- `audit.list` 契约已存在，不新增 action，仅页面化消费。

### 7.3 FR-026 阶段 2（Wave 2）

| action | 说明 |
|--------|------|
| `mip.admin.adminAccounts.loginRecords` | 登录记录列表（账号/时间/结果/IP/设备/失败原因） |
| `mip.admin.adminAccounts.passwordLogin` | 手机号密码登录（区别于验证码登录） |
| `mip.admin.roles.create` | 新增角色 |
| `mip.admin.roles.update` | 编辑角色 |
