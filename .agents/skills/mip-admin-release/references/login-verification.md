# 管理后台登录链路验证

适用于 CloudBase 正式或测试后台的密码、六位登录码或二维码确认失败。先审计和拉取最新代码，按调用链检查两端、BFF、管理云函数及认证存储，不先改密码或替换全部回调。

## 密码与账号

- 正式与测试使用独立 MySQL 认证 schema、账号和密钥。读取目标账号存在性，报告只保留数量与是否存在，不输出手机号、微信身份、密码哈希或 pepper。
- 使用已配置且获授权的测试账号验证目标 origin 的真实登录、管理会话和退出。测试账号通过不证明用户报告的另一个账号已通过；未拿到该账号标识时明确待核对。
- 密码哈希依赖目标自己的 pepper，不能直接复制生产密码或认证表。历史一次性账号迁移脚本已删除，新管理员使用现有小程序确认与本人设置密码流程。
- 有管理权限的用户可用自己的微信确认新后台登录，再在账号菜单“设置 / 修改登录密码”。修改凭证交给用户本人完成；不得给未知账号重置密码、借用维护者身份或新增权限。

## 小程序确认与回调

1. 回读目标管理 API 和 BFF 的配置，核对 `MIP_ADMIN_WEB_LOGIN_CONFIRM_URL`、`MIP_ADMIN_WEB_LOGIN_MIGRATION_URL`、HMAC 对应关系和 QR 环境；不输出秘密值。同步云端和本机覆盖配置，防止下次部署回退。
2. `MIGRATION_URL` 是保留的兼容字段名：当前 CloudBase 的 `9xxxxx` 六位码与 `z_` scene token 仍走此回调。正式配置中的两条 URL 应对应正式 BFF，测试配置中的两条 URL 应对应测试 BFF；只改主回调会让保留范围走错目标。确有历史入口仍需分流时，以实际调用链和配置为准保留明确覆盖，不把它当成日常发布前提。完成后回读两条 URL 和对应 HMAC 一致性（只输出布尔值），再做实际微信确认，不能以配置修正宣布登录闭环通过。
3. 由真实网页创建 challenge，在已登录且有管理员权限的小程序客户端输入其六位码，点击现有确认按钮。浏览器等待自身 challenge cookie 对应的确认，取得真实会话并展示非空业务数据，再退出。
4. scene 流程同样使用真实 challenge、真实小程序页面与按钮。不要伪造确认主体或只用签名请求替代微信身份。BFF 成功消费确认后的轮询状态是 `AUTHENTICATED`；单次消费、cookie 绑定和超时会让已用 challenge 失效，不重复消费后再判定失败。
5. 对本次受影响入口分别测确认、会话和退出；二维码图片生成只证明生成接口工作。微信开发者工具调用真实云函数与手机实际扫码是两层证据，不能互相替代。

后台域名提示从 `brand.adminConsoleDomain` 读取。显示文案更新需随下一次微信版本发布，后台回调修复不依赖重新上传小程序。上传仍执行仓库完整门禁并遵循当次授权范围。

## 登录后的读取

验证来源拒绝、错误密码、Secure/HttpOnly/SameSite cookie、退出后会话拒绝，以及查询 allowlist 内各模块的非空 DTO。列表修复要验证真实页面、中文筛选、空结果与分页合同；不能把 HTTP 200 或空数组当作业务成功。

出现仅非空列表失败时，检查 SQL 并发与池队列。每行并发加载两项关联会把整页变成大量查询；按 app 作用域批量读取、按稳定键分组，保持排序、金额与分页合同。回归测试应先能复现实际队列边界，再验证查询数量与 DTO 隔离；不为了压测写生产业务数据。

执行记录放入 `docs/mip/evidence/`，只提交脱敏检查与摘要；账号、cookie、scene、原始环境、日志和截图放在忽略的私有目录。全流程读取通过不代表所有新增、支付、权限变更和真机场景已验收。
